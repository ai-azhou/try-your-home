# 户型结构台 · 设计系统（D1，D3 改玻璃 / 白模 / 布局，S2a 加测量 / 楼层 / 新构件 / 数字框）

> 给下一轮实现者的规格。每条都写了「为什么」；改的时候先看理由还成不成立。
> 令牌的唯一来源是 `src/styles/index.css` 的 `@theme`；2D 画法常量在 `src/ui/canvas2d/style.ts`；3D 材质在 `src/three/materials.ts`。本文和代码冲突时以代码为准，并回来改本文。

## 1. 方向

**一块浮在淡薄荷 / 淡紫柔光里的白模工作台：画布铺满全屏当主角，四周只浮几块磨砂玻璃卡；颜色只用来说结构的话。**

- 画布是主角（参考图 2）：2D / 3D 都铺满，卡片浮在上面，不切分屏幕。旧界面「第一眼不知道操作哪里」的根因是面板和按钮在抢画布，所以这里任何时刻屏幕上最多：左一列工具、顶一条模式、右一张卡、底一条「下一步」。
- 白模 + 粉彩（参考图 1/4）：结构本身用黑白灰（像建筑模型），粉彩只出现在「需要你注意」的地方。这样一张图里有颜色的地方就是要看的地方。
- 玻璃只给浮层，不给内容：卡片是玻璃，卡片里分组用更实的白块（`.tile`），避免「玻璃套玻璃」发灰发糊。
- D3（本人评审「玻璃感偏弱」）：玻璃要读得出来，前提是**底下有东西可透**——平灰底上的半透明白卡只会像白卡。所以底色加了三团有方向的柔光（左上白、右上淡紫、左下淡薄荷），卡片放在柔光边缘上，透出来的是有颜色的雾，卡片边缘内外的点阵一实一虚，玻璃就成立了。

### 2.2 字体

- 中文：系统栈 `PingFang SC → Hiragino Sans GB → Microsoft YaHei → Noto Sans CJK SC`。
- 拉丁和数字：Manrope Variable，**只打包拉丁子集 woff2（约 25KB）**，`@font-face` 直接指向 `node_modules/@fontsource-variable/manrope/files/`，构建时内联，运行时零请求。数字一律 `.num`（等宽数字 `tabular-nums`），尺寸跳动时不抖。

### 2.3 圆角、间距、阴影、玻璃

- 圆角：药丸 `999`；大卡 28–32；中卡 22；内块 16–20；小块 11–14。**越靠外越圆**，嵌套时内圆角 = 外圆角 − 内边距，看起来同心。
- 间距：4 的倍数。浮层离屏幕边 20（手机 12）；卡片内边距 16；卡片里分节间距 16；字段间 10。
- **磨砂玻璃配方**（D3，`src/styles/index.css` 的 `--glass-*`）：
  - 填充 `--glass-fill`：白色 158° 斜向渐变 **58% → 30% → 40%**（左上最实、中段最透），再叠一片左上角的镜面高光（径向，白 42% → 0）。D1 是 80% → 62%，太实，透不出底色。
  - 模糊 `--glass-blur`：`blur(26px) saturate(185%) brightness(1.04)`。提饱和是关键：柔光透过来是「有颜色的雾」，不是发灰。
  - 边 `--glass-edge`：左上 1px 内高光（白 85%）、右下 1px 弱高光（28%）、一圈 22% 白内描——光从左上来，和画布亮区、3D 主光同向；`--glass-ring` 0.5px 墨紫发丝线，白底上也有边界。不用伪元素做渐变描边：右侧卡会内部滚动，伪元素会跟着内容滚走。
  - 投影：近 `0 2px 6px -2px` 8% 墨 + 远 `0 26px 52px -24px` 30% 墨紫（`rgb(48 44 104)`）。远影带一点紫，和底色同族，不脏；单层大投影会脏、单层小投影没浮感。
  - `.glass-strong`（弹层：菜单、问题卡、交给 Agent、二次确认）：填充 90% → 78%，内容密，优先可读；投影更远（36/72px）。
- **主次**（不要每个元素都玻璃化）：
  | 级别 | 类 | 给谁 |
  |---|---|---|
  | 一级玻璃 | `.glass` | 右侧卡 / 手机抽屉、顶栏方案胶囊、三态分段的轨道、左侧工具栏、下一步条、缩放条、画中画框 |
  | 弹层玻璃 | `.glass-strong` | 下拉菜单、图层、问题卡、导出图片、交给 Agent、转换报告 |
  | 二级玻璃 | `.glass-chip` | 单独浮在画布上的小圆钮（图层 / 问题 / Agent）、热点的白环、画中画上的标签和换位钮。同一套高光和发丝线，模糊 14px |
  | 实心白块 | `.tile` / `RoundButton tone="tile"` | 卡片**里面**的分组、列表项、按钮：白 62% + 顶部 1px 高光，不模糊（玻璃套玻璃会糊） |
  | 实心色 | 墨 / 薄荷 / 粉彩 | 选中态（墨底白字、薄荷滑块）、热点的粉彩盘、主按钮 |
- **手机降级**（backdrop-filter 每帧都要重算模糊，3D 画布在底下时尤其贵）：`< 768px` 时 `--glass-blur` 降到 `blur(14px) saturate(160%)`，填充加实到 80% → 64%；`.glass-chip`（热点、小钮）**不模糊**、填充 94% → 84%——它们数量多、在 3D 里每帧移动；底部抽屉（`.glass-strong`）填充 97% → 92%——它整块盖在平面上，下面的问题针、薄荷选中会透成色斑。系统开了「降低透明度」（`prefers-reduced-transparency`）或浏览器不支持 backdrop-filter 时，退成实心浅白卡，其余配方（高光、发丝线、投影）不变，层级照样分得出。

| 场景 | 时长 / 曲线 | 为什么 |

| 区域 | 职责 | 为什么在这 |
|---|---|---|
| 顶栏左：方案胶囊 | 文件名 + 保存状态（已自动保存 / 本地保存失败 / 服务模式下「Agent 改完会自动刷新」或「有改动未导出」）；点开是文件菜单（打开、导入户型图、导出 ⌘S、转换报告、左右 / 上下镜像、新建空方案、示例、语言） | 文件操作低频，收进一个菜单 |
| 顶栏中：三态分段 | 原始 / 改造 / 对比，改造上挂改动数 | 全局最重要的开关，放正中；数字告诉用户「改造里有东西」 |
| 顶栏右 | 图层（底图、尺寸、把握程度、3D 顶面）、待核对（柠檬角标）、交给 Agent（**次要**：玻璃圆钮 + 淡紫图标，`A`） | 交给 Agent 任何时候一步可达，但主入口在检查器 / 下一步条（§8），这里只是常驻退路，不和它们抢（D2 修 PM 验收：之前选中墙时屏幕上同时有三个「交给 Agent」） |
| 左上标题 | 方案名（细）+ 当前模式（粗）+「使用 65.8㎡ · 含墙 79.2㎡」/ 间数 / 待核对或 −拆 +加 ~改 | 不看任何面板就知道「我在看什么、还差什么」。面积用 core `planStats` 的 `netArea`（使用面积，不含墙）和 `grossArea`（含墙，上限估算）两个数、两个短标签；悬停出一句口径：**含墙面积是上限估算，不等于购房合同上的套内 / 建筑面积**——只写一个数时业主会当成合同面积（PM 实测）。core 没给 `netArea` 时退回 `area` |
| 左侧工具栏 | 2D 为主时是编辑工具；3D 为主时同一位置换成视角工具（斜视 / 俯视 / 平视 / 顶面 / 复位） | 「2D 改结构、3D 看结果」：工具跟着主画布走，不会出现在 3D 里按「画墙」没反应 |
| 右侧卡（一次只一张） | 转换报告（打开时）→ 底图卡（底图工具）→ 选中 → 检查器；原始模式没选中 → 待核对列表；改造 / 对比没选中 → 改造清单 | **选中什么才出现什么**；同一位置换内容，眼睛不用找 |
| 底部中：下一步条 | 永远只有一句话 + 一个按钮（见 §8） | 解决「不知道该干嘛」 |
| 右下：撤销 + 缩放 | ↶ / ↷（当前模式的历史）、− / 适配 / + | 参考图 2；撤销是编辑台的基本退路，放在手边 |
| 左下：画中画 | 另一个视图的实时小窗，右上角换位；两边选中联动 | 见 §4 |

**左列按实际高度排**（D3，`ToolRail` 的 `useLeftColumn`；PM 实测：3D 工具栏多了「白模」「导出图片」后底部碰到画中画，1440×800 还会压到标题的面积行）：工具栏顶 = 标题块底 + 16px（实测，不写死）；工具栏底会碰到画中画时，画中画往右让到工具栏旁边（`store.pipShift`，`layout.pipRect`、2D 适配、3D 取景都用同一个值，平面不会被让过去的画中画压住）；整根工具栏都放不下（很矮的窗口）时去掉文字标签，只留图标和悬停提示（`store.railCompact`）。

**底图找不到**（D3，`ui/underlay-check.ts`）：方案里的底图是相对路径、服务模式下 404，或浏览器直接打开的方案里底图是相对路径（取不到）时，顶部轻提示「底图没找到，可以重新导入」+「重新导入 / 知道了」；已经有别的提示（比如「已转换旧格式方案」）时排在它后面。底图卡里同样标出来。「重新导入」只换图片本身，比例 / 原点 / 镜像保留。

检查器卡片超高时内部滚动，**操作行（交给 Agent / 拆除）吸底**，主按钮永远看得见；承重 / 外墙的二次确认卡也放在吸底区里、操作行上方（不会被吸底行盖住）；没有检查器时（门窗工具在受保护墙上开洞）浮在底部中间；Agent 待确认提议放在检查器第二行（把握程度之后），因为它是这面墙上最该先处理的事。

**适配不被压住**：「适配」在四周浮卡（顶栏、标题、左工具栏、左下画中画、右侧卡预留区、底部下一步条带、右下缩放条；手机是顶栏两行、右上画中画、底部工具坞 + 下一步条）之外，找能把平面放到最大的矩形（`layout.freeRect`），3D 相机用同一个矩形做画面偏移。编辑时不自动重新适配（画面不跳），只在载入、改窗口尺寸、按 `F` 时适配。

**S2a 加的四个入口（都不占新面板）**：
- **楼层切换**：只有多层方案才出现。桌面在左上标题块第三行下面（`1F / 2F` 药丸 + 齿轮），手机在画布左上角（指北针右边）。齿轮弹层里改名称、标高、层高，「其他层淡显」「3D 只看这一层」两个开关，「新建楼层」「删除这一层」（只删空楼层）。楼层是原始结构，只在原始模式里改。为什么放标题块：标题块本来就回答「我在看什么」，「哪一层」是同一个问题。
- **更多结构**：左侧工具栏在「房间」和「底图」之间多一个「更多结构」（图标 = 几何形组）。点开是二级菜单：柱、管道井、楼梯、挑空，分隔线下「新建楼层」。选中其中一个工具时，这个入口本身变墨底并换成那个构件的图标和名字，看得出「现在在画什么」。工具栏只多一个按钮，不多一排。
- **指北针**：2D 主画布右下、缩放条左边（手机左上角）的二级玻璃圆钮，指针指向方案的北（`plan.north`）。按住拖动旋转（靠近 45° 的整数倍吸附，⇧ 每 15° 一档），双击回正。3D 为主时不显示。
- **保存**（服务模式才有）：顶栏右侧图层按钮左边一枚药丸「保存 ⌘S」，有未保存改动时墨底，存完退成玻璃；方案胶囊的状态写「有改动未保存 · ⌘S 写回」。服务模式下 ⌘S = 写回方案文件，文件菜单里的「导出 JSON」照旧可用。

**手机（< 768px）**：顶栏两行（方案胶囊 + 问题 + 图层；三态分段铺满一行）；画中画缩成 108×108 放右上；工具栏变底部工具坞；右侧卡变**底部抽屉**（58% 高，拖把手或上滑到 86%，下滑关闭；选中后画布自动把构件平移到抽屉上方，取消选中回到适配）；交给 Agent 变全宽底部抽屉；下一步条在工具坞上方；缩放靠双指。标题块在手机上不显示（顶栏胶囊里有方案名）。

## 4. 2D 和 3D 的关系：主画布 + 画中画

**决定**：一次一个主画布（铺满），另一个在左下画中画小窗里实时显示；点小窗右上角的「⇄」或按 `Tab` 互换。

**理由**：
- 分屏在 1440 宽、两侧还有卡片时，每边只剩 ~450px，平面图和 3D 都看不清；户型图本来就是横竖都要的形状。
- 纯切换会丢掉「改 2D 时立刻看到 3D 变化」这件事，而这是工具的核心价值。画中画让 3D 一直在眼角，改一个层高、换一个墙类型，小窗里马上变。
- 两个视图常驻（WebGL 不重建），换位只是改尺寸位置；选中状态是同一份，所以在任一边点选，另一边同时高亮（薄荷）。
- 画中画里也能点选（2D 小窗点墙、3D 小窗点墙都有效），也能在 3D 小窗里转视角，但不能缩放平移（避免误操作）。

## 5. 2D 平面图画法

### 5.1 画布

- 背景点阵：1m 一个点（缩小后 2m），点 1px、墨色 13%；跟着平移缩放。**用点不用线**，不和墙线打架。
- 平面像一块白模放在灰台面上：所有房间和墙的外轮廓先画一层白底 + 两层投影（`#slab` 滤镜）。
- 线宽、字号都按屏幕像素写（除以缩放 k），缩放时字不变大变小。

### 5.2 墙（深 = 受保护，浅 = 可动）

| 类型 | 画法 | 为什么 |
|---|---|---|
| 承重 `bearing` | 墨色 `#1f232a` + 45° 浅斜线 | 业主看开发商图时「涂黑的是承重」的习惯；斜线让它和外墙分开 |
| 外墙 `exterior` | 石板灰 `#3c424b` 实心 | 同属受保护，比承重浅一档 |
| 非承重 `partition` | 中灰 `#adb3bc` 实心 | 明显比受保护的浅：能动的墙看起来就「轻」 |
| 矮墙 `half` | 浅灰点纹 | 点纹 = 不到顶 |
| 玻璃 `glass` | 天青填充 + 天青描边 + 中线 | 玻璃的习惯画法 |
| 矮墙 + 玻璃 `half-glass` | 点纹 + 粗天青中线 | 两种信息叠在一起 |

- **按类型并成多边形画**（core 墙足迹按洞口切段 → polygon-clipping 并集）：外墙 → 承重 → 隔墙 → 玻璃 → 半玻 → 矮墙依次占位，后来的扣掉已占的部分，墙角归更「硬」的那面，T 形、L 形交接没有缝。core 的足迹是沿中心线的矩形，L 角外侧会缺 t/2 见方一块，界面在画图前把 L 形相接的墙端延长对方厚度的一半（`ui/render-plan.ts`，只影响显示，不改数据），2D 和 3D 都这么做。
- 墙按洞口切段画，洞口处露出门槛白。
- 弧墙按矢高画条带（core 的 `wallFootprint`）。S2a：弧墙上能放门窗（core 按弧长定位），窗的两条墙面线、玻璃中线、落地窗双线、飘窗外线、门洞虚线、栏杆点线都沿弧细分画（每 60mm 一段），分扇短横垂直于该处切线；平开门扇按洞口两端的弦画。玻璃墙中线也沿弧画。超过半圆（优弧，圆心角 > 180°）照样画，墙角接缝用 core 的精确切向。

### 5.3 门窗符号

| 类型 | 画法 |
|---|---|
| 平开门 | 门扇 2.4px 墨线（从铰链点开到 90°）+ 1px 浅弧 + 扇形 3.5% 墨色填充 + 铰链圆点。门扇画在墙面上（不是中线上），开向一眼看出 |
| 推拉门 | 墙厚里两片错开的白色细长扇（各 56%，中间重叠） |
| 门洞 | 墙两面各一条浅虚线（虚线 = 上方有过梁） |
| 窗 | 淡天青底 + 两条墙面细线 + 天青玻璃中线；分扇处画短横 |
| 落地窗 | 中线变双线 |
| 飘窗 | 窗 + 外侧一道虚线；飘窗台是单独的房间（斜纹地面 + 「+0.45 m」） |
| 未封阳台 | 点线栏杆 |
| 入户门 | 门外一个墨色小胶囊「入户」 |

### 5.4 房间、梁、尺寸、底图

- 房间：白色；标签 = 名称（13.5px 650）+ 面积（Manrope），层高和全屋默认不同时多一个灰胶囊「层高 2.55」；文字带同色描边光晕，梁的虚线从字下穿过时不打断字。
- **标签排布**（D3，`src/ui/canvas2d/labels.ts`；PM 用 13 间房的真实户型实测：客厅名字被问题针盖住、相邻小房间压字）：**房间名永远不消失**。每个标签整块落在自己房间里（离墙内皮 ≥ 3px）、不压问题针、不压别的标签；按顺序试：完整（名称 + 面积 + 层高胶囊）→ 去掉胶囊 → 长名在「与 / 和 / 及」处换两行 → 缩字号 → 只留名称 → 更小 → 缩写成「套间通…」→ 最后才改成**悬停 / 选中时显示的墨色浮签**。每一档都先在房间里挪位置（标签点优先，再按距离试房间里的网格点），挪得开就不缩。小房间先排（能放的地方少），大房间后排、有地方让。同一处的几个问题针（比如两个都问客厅）左右摊开，不叠成一个；入户标签被针盖住时沿墙挪开。
- 梁：在剖切面以上，按制图习惯画**虚线轮廓** + 3.5% 填充。选中 / 悬停变薄荷。
- 尺寸：默认只画总宽、总深（外侧 30px，白胶囊里写米）；选中墙 / 梁时沿构件另画一条**墨色胶囊**尺寸；选中洞口画洞宽（mm）。不默认画满尺寸链——那是旧界面「一堆细线和小字」的来源。
- 底图：图层里打开，按 `mmPerPx` 和 `origin` 放在平面坐标里，透明度可调，打开时平面整体压到 82% 让底图透出来。

### 5.5 状态

| 状态 | 画法 |
|---|---|
| 悬停 | 墙 / 洞口叠 45% 薄荷；房间变 `mint-50` |
| 选中墙 | 实体段薄荷实心 + 深薄荷描边；洞口处薄荷虚线；两端白色圆柄；沿墙一条墨色尺寸胶囊 |
| 选中洞口 | 洞口范围薄荷 + 两端方柄 + 洞宽 |
| 选中房间 | 整块 `mint-100` + 薄荷描边（参考图 4） |
| 多选 | Shift / ⌘ 点击追加；检查器显示多选卡 |
| 把握程度（图层或打开问题时自动） | 推断 = 柠檬虚线框；不知道 = 柠檬斜纹 |
| 改造态 | 显示重放后的结果；受保护墙悬停 / 选中时旁边出白色锁热点 |
| 对比态 | 未改动的全部退灰；拆掉的 = 珊瑚斜纹 + 珊瑚虚线（门窗画珊瑚色符号）；新增 = 钴蓝实心 + 外发光；修改 = 钴蓝虚线框（房间是钴蓝底 + 「改」标）；Agent 待确认的提议 = 淡紫斜纹虚线框 + 淡紫热点 |
| 吸附提示（画墙工具，`?state=draw`） | 光标处薄荷圈；吸到端点 / 墙中线 / 洞口端 / 网格 / 角度时圈变大，旁边墨色胶囊写吸到了什么 + 当前长度；第一下之后拉出 120mm 薄荷虚线橡皮筋墙 |

### 5.6 新构件（S2a）

| 构件 | 画法 | 为什么 |
|---|---|---|
| 柱 `column` | 实心：承重 `#1f232a`（和承重墙同色），装饰柱中灰 `#8e949d`；画在墙上面 | 开发商图里柱就是涂黑的方块；墙垛贴着墙也看得出 |
| 管道井 `shaft` | 白底 + 45° 石板灰斜线 + 墨色轮廓；够大时中间一个白胶囊写「烟道 / 管井 / 风道」 | 斜线 = 「这里不能动」，和承重墙同一种语言；拆不了，检查器里一块墨色锁说明 |
| 楼梯 `stair` | 白底 + 墨色轮廓 + 沿上行路径的踏步线（按踏步数等分）+ 从起点（低处）出发的箭头，起点处墨色小胶囊「上」 | 建筑制图的习惯画法；箭头永远指上行方向 |
| 挑空 `void` | 极淡底 + 灰色虚线轮廓 + 外包框对角打叉；够大时中间写「挑空」 | 制图里挑空 / 楼板开洞就是打叉 |

- 画法：柱点一下放下（400×400 承重柱，检查器里改形状、尺寸、旋转、类型）；管道井、楼梯、挑空都是点两下拉矩形（旁边墨色胶囊写宽 × 深）。楼梯沿长边、从第一下那头往上走，通到上一层，同时在上一层同一位置自动开一个「楼梯洞」挑空（两条记录同组）。最上一层不能放楼梯，提示先新建楼层。
- 点选顺序（`ui/levels-ui.pickAll`）：柱 → 门窗 → 墙 → 管道井 → 梁 → 楼梯 → 挑空 → 房间：小而实的先认，大面积的房间最后。悬停 / 选中和墙一样叠薄荷。
- 对比态：新增钴蓝、拆掉珊瑚斜纹虚线、未改动退灰，和墙一致。
- **其他楼层**：多层方案的 2D 只画当前层；其他层的墙体轮廓用墨色 34% 虚线 + 5% 填充叠在上面，对位用、不接收点击（楼层弹层里可关）。适配按全部楼层的外包框，切层时画面不跳。

### 5.7 测量（S2a，规格见 `docs/specs/测距.md`）

- 触发：选中一面墙 → 按住 ⌥ / Alt → 悬停另一面墙（悬停到门窗上算它的宿主墙）；松开就消失。移到胶囊上时保持（只有悬停到另一面墙才换目标）。触屏：检查器操作行的尺子按钮「测距」→ 再点另一面墙；再按一次或 Esc 退出，下一步条提示「测距：点另一面墙」。
- 画法：两面墙足迹描 1.2px 洋红边 + 8% 洋红底；标注线 1.5px 洋红，两端垂直短线；从墙面到标注线的延长线 1px 洋红虚线；胶囊洋红底白字、白描边，数字 mm 取整千分位（「1,900」）。斜墙最近点另附「Δx · Δy」小胶囊。相交时只出「相交」胶囊。
- 胶囊悬停出一句「净距 1,900 mm · 中心线 2,100 mm」，点一下复制数值。测距时不画选中墙的长度胶囊（免得两个胶囊叠在一起）。
- 数字来自 core `measureWalls`（方案几何），缩放不变。

## 6. 3D 观感

- **两种显示风格**（3D 视角工具栏里「白模」开关，按下 = 白模）：
  - **结构色**（默认）：见下一条。
  - **白模**（D3 精修，对标参考图 1、2）：给生图 / 生视频模型当几何底图用。中性白、和墙类型无关：墙面 `#f4f4f3`、墙顶 `#f7f7f6`、地面 `#e8e8e6`、飘窗台 `#f0f0ee`、底板 `#f2f2f1`——**明度只差一点，体积交给光和 AO**。不画棱线（真的白模没有描边）；各房间的地面并成一整块（core 给的是每间房一块地面，相邻房间的接缝在白模里是一道道细线，喂给生图模型像地砖缝）；玻璃是极淡的冷白（`#eef3f7` 26%）；隐藏热点、标签胶囊、顶面轮廓、选中 / 悬停高亮和问题针，也不响应悬停；对比态的珊瑚 / 淡紫幽灵盒子不画。平视时朝相机的外墙**直接不画**（连同墙上的窗扇），像剖开的模型，不留半透明幽灵墙。
  - 实测色阶（斜视白底导出，sRGB）：墙顶 247–254、朝光地面 229–237、背光墙面 210–219、贴墙地面 198–218、墙脚交线 ~155。不过曝（最亮只在墙顶）、不发灰（地面主体 > 225）。
- **导出图片**（视角工具栏「导出图片」）：用当前相机机位和朝向，去掉为浮卡做的画面偏移，再**按模型实际轮廓取景**（所有 `userData.fit` 网格的顶点投到屏幕取外接框，四周留 7%，补成画面比例，用 `setViewOffset` 裁——透视不变，只是模型居中占满）；用户放大到只看局部时保持原取景。按 2 倍像素渲染 PNG（桌面 2880×1800），文件名「方案标题-白模|结构色-视角.png」；导出时隐藏高亮层和顶面轮廓（`userData.ui`），热点本来就是 DOM 不进 canvas；背景可选纯白 / 透明。透明背景下模型和底板边缘干净（抗锯齿边是正确的预乘 alpha，没有白边灰雾），窗玻璃本来就是半透明的、会透出合成底色。两种风格都能导出。
- **白模 + 墙顶切面上色**：墙的侧面全是白模（`#f7f8f9`，粗糙度 0.92），**墙顶面按类型上色，和 2D 画法一一对应**（承重墨色斜线纹理、外墙石板灰、隔墙中灰、矮墙浅灰、玻璃天青半透明）。为什么：俯视时 3D 就是「立起来的平面图」，用户在 2D 学会的颜色在 3D 里直接能用；侧面保持白模，整体仍是参考图 1/2 那种干净的模型感。
- 地面比墙暗一档（`#e6e8ec`），飘窗台是升起的浅色台子并标「+0.45」。
- 底座：方案外扩 0.7m 的圆角白台（像建筑模型的底板）+ 台面接触阴影（影子平面离台面 1cm：贴得太近大户型远机位下会 z-fighting 出横纹） + **底板下面再一圈贴着方案范围的软影**，模型「放在桌上」而不是飘着；软影只覆盖方案外扩 2.5m，不会把整张图四周罩灰。
- 几何来自 core：`buildSolids` → `three/geometry` 的 `mergeByKind` / `solidToGeometry`，门扇、窗扇、栏杆来自 `buildFixtures`。core 按全屋所有高度统一分层，一面墙会切成好几层，界面把同形状、上下相接的层并回一块（`three/pieces.stackSolids`），否则墙面上全是横棱线。按显示状态（正常 / 对比退灰 / 新增 / 平视剖切）分组各自 buildSolids，各用一套材质。
- 点选：射线命中点换回平面坐标（x·1000, z·1000）调 core `hitTest`（地面只认房间、梁只认梁）；选中 / 悬停单独生成该构件的实体，用 polygonOffset 叠一层，不给合并几何换材质。
- 材质分开：玻璃 / 窗扇半透明天青（不写深度，渲染顺序靠后）；门扇白色、开 68°（`pieces.DOOR_ANGLE`，全工程一个值）；窗框浅灰细条；梁浅灰，从梁底挂到层高。
- 灯（D3）：**柔和天光为主 + 一个主光方向**。半球光（天白 / 地 `#c4c7ce`，1.0）+ `RoomEnvironment` 环境光（three 自带，**不联网**，0.36–0.42，主要给玻璃反射）+ 暖白主光 1.05（水平从南往西偏 58°、仰角 66°，PCF 软阴影半径 7、阴影强度 0.55）+ 右前一盏 0.22 的冷色回光。为什么这个方向：斜视时朝相机的墙面亮、朝右的墙面暗一档、墙顶最亮——参考图 2 的三段明度；影子落向东北，斜视看得到墙东侧地面上的一道影子、读得出墙高，又不会把整间房罩暗（D2 的主光从左上后方来，看得见的墙面全在背光里）。梁不投影：俯视时梁影在地面上是一道道灰带，和墙影混在一起读不清。色调映射 Neutral，曝光 0.92。
- **AO**（D3，`src/three/ao.ts`）：不用后处理（N8AO 在这套色调映射下洗白、软件渲染下看不出、透明导出也不稳）。户型是竖直挤出的，AO 几乎都发生在墙脚和阴角，所以在平面上烘一张场贴图（25mm/像素），所有不透明材质的着色器按世界坐标 (x, z) 取样：
  - 地面 / 飘窗台 / 底板：到墙体距离的两段指数衰减（贴墙 7cm 的接触暗线 + 38cm 的软边），阴角再加深；
  - 竖直面：贴地 36cm 的墙脚暗带 + 墙体轮廓凹角处的一团暗（墙与墙的阴角，两侧墙面都暗下去）；
  - 墙顶、窗台顶这些「在墙里」的朝上面跳过；AO 主要压环境光（全量）和主光（85%），下限 0.4，墙脚交线不会死黑。
  - 场贴图按墙和洞口缓存，改一面墙才重算（13 间房的方案约 20ms）。`?ao=0` 可关，对比截图用。
- 相机：透视 26° 窄视角（模型感，不畸变）。预设：**斜视**（方位 24°、仰角 50°，北朝里，和 2D 朝向一致）/ **俯视**（89°）/ **平视**（20°，**朝相机一侧的外墙自动剖开**：结构色半透明、白模不画，看得到里面的梁、窗台、门洞高）。「朝相机一侧」= 墙面大致朝相机、且墙外 25cm 处多数位置不在任何房间里（外立面；D2 只剖最外一圈，阳台后面的南墙剖不掉）。相机会让开左右面板，模型居中在没被挡住的区域。
- **看得出高度**（只看俯视白模看不到梁和层高）：
  1. 每间房在自己的层高画一圈细线轮廓（「顶面」开关，默认开），层高不同的房间旁边浮一个胶囊「卫生间 · 2.55 m」；选中的房间顶面填一层淡薄荷。
  2. 梁从梁底挂到层高，选中 / 悬停时梁下浮「梁底 2.55 m」。
  3. 检查器里有**立面小图**（墙：洞口、窗台、洞顶、过梁、墙高）和**剖面小图**（房间：层高、梁底、地面抬高）。这是读高度最准的地方。
- 选中：整件构件薄荷（顶面深一档）+ 深薄荷描边；洞口选中时整个洞口体积罩一层薄荷。悬停只换侧面颜色。
- 对比：未改动退灰；拆掉的 = 13% 珊瑚半透明 + 珊瑚描边（够淡，新加的钴蓝能透出来）；新增 = 钴蓝；Agent 待确认的开洞 = 淡紫半透明盒子 + 淡紫热点。
- **楼层**（S2a）：默认全部楼层上下叠放（core `buildSolids` 按层出绝对标高，上层楼板 120mm、只盖已画的房间和墙，扣掉挑空）；楼层弹层里「3D 只看这一层」= 只画当前层（core `onLevel` 视图，标高保留，看得到楼梯伸上去）。多层时取景半径算上总高度、目标点抬高。点选按命中点高度定楼层再 hitTest。新构件：柱顶墨色斜线（承重色）、管道井顶石板灰、侧面白模；楼梯踏步用飘窗台的浅色；楼板用地面色。白模下统一白。层高胶囊、问题针、梁底标签都加楼层标高。
- 热点：DOM 覆盖层每帧投影（`src/three/Overlay3D.tsx`），和 2D 用同一个 `Hotspot` 组件。不用 drei `<Html>`（React 19 下增删会报同步卸载的错）。

### 7.2 检查器里的编辑

- 所有编辑都生成 core 的 Change：原始模式 = **纠正读图**，`bakeChange` 烘进 base（不需要二次确认，也不存 confirm）；改造模式 = 追加进 changes（同一构件同一字段连续改合并成一条，拖动一次 = 一条或一组 group）；对比模式只读。改造态里会让承重 / 外墙被拆或开洞的编辑（含拖动受保护墙上的洞口），重放报 needsConfirm 时先弹二次确认，确认后写 `confirm: {by: '业主'}`。
- 墙（原始模式）：「在此处分段」剪刀 = 在最近一次点选的位置分段（core `splitWall`，穿过洞口时提示）。
- **受保护改动的二次确认**：拖动里碰到受保护构件时，改动只是预览（`unconfirmed`）：答「我确认」之前不进自动保存，也不能写回或导出；切模式当「先不改」。确认卡写明这次动到了哪些构件。
- **拆墙后墙占地怎么算**（`actions.ts` `offerFootprint`，core `merge-rooms.ts`）：合成一间（两侧各一间、高差和计面积一致时才有）/ 算给某一侧（两间都留着；这一侧每间收下自己贴着的那段，一侧多间也不留缝；不压别的房间）/ 先不管（留缝）。房间贴墙的范围用墙带和房间多边形求交（`roomSpanOnWall`），房间比墙长也算得出来。
- **只拆一段**（改造模式检查器「只拆一段」）：输入从 a 端量的范围，画布标红；范围里的门窗不能留在拆掉的墙上，所以可选「连门窗一起拆」或「收缩范围，避开门窗」（取范围里最长的无门窗一段）；写 `remove wall` + `range`，拆完走占地询问。展开时滚到面板中间，免得被吸底操作行盖住。
- **房间工具**：围出的区域压住同层房间（重叠 ≥ 0.3 m²）就不建，提示压住了哪几间（`roomsOverlapping`）。
- **数字框**（S2a，`kit/NumberField`，所有数字输入都用它，替换了加减号步进器）：Figma 式。点数字 = 全选，直接打字替换；回车或失焦生效，Esc 还原（只还原数字框，不会顺带取消选中）；↑↓ 按步长调、⇧ ×10；按住字段名左右拖改值（每 4px 一个步长，⇧ ×10，光标变左右箭头）；超出范围夹回边界，框下一行珊瑚小字「最大 600 mm，已夹回」2.4 秒；接受全角数字和千分位逗号。为什么：业主手里有量好的尺寸，要的是「打进去」，不是点 30 下加号。
- 墙的弧度：检查器里一行三个数字框「矢高 mm / 圆心角 ° / 半径 mm」，用 core `arcParams`、`bulgeFromAngle`、`bulgeFromRadius`；直墙时半径显示「直墙」占位。圆心角范围 ±340°（正 = 朝法向 n 鼓），改半径时保持当前的鼓向和优 / 劣弧。长度显示弧长，旁边小字「弦 x.xx m」。
- 门窗：分扇 1–4 扇（等分）。房间：名称（文本框）。
- 墙：类型（六选一，受保护的带锁）、厚度、矮墙实体高度；拆除（改造态）——承重 / 外墙先弹**珊瑚斜纹确认卡**（「我确认，记一条拆除」/「先不拆」），确认后写进 `confirm`。
- 门窗：七种类型、宽、离地、洞顶、离 A 端；平开门的铰链（A/B 端）和开向（**用房间名说**：「开向 次卧 | 过道」，比「朝法向」好懂）；封掉（改造态）。
- 房间：层高、地面高差（S2a 起允许负值：正 = 抬高如飘窗台，负 = 降板如卫生间 −0.05，范围 −0.60 ~ +1.20 m）、计入面积。梁：梁底、梁宽。
- 柱：形状（方 / 圆）、类型（承重 / 装饰）、宽深或直径、旋转；拆承重柱和拆承重墙一样先二次确认。管道井：类型、宽深（矩形时），一块墨色锁说明「不能拆、不能占」；改造态按拆除由 core 拦下并提示「管道井 / 烟道不能拆」（原始模式删 = 纠正读图，允许）。楼梯：通到哪层、长、梯段宽、踏步（默认按每步 ≈170mm 自动）、每步高度。挑空：宽深。
- Agent 的待确认提议：淡紫卡片「我确认 / 撤销这条」。
- 改造清单每条可撤销（悬停出现，手机常显）。

## 8. 「下一步」规则

底部条永远只有一句话 + 一个按钮，按优先级取第一条：

1. 有选中 → 墨色「拖白色圆点改墙角，拖中间的菱形拉成弧墙 · ⌫ 删除」（按构件类型给一句怎么改，**无按钮**）。「交给 Agent」只在检查器吸底操作行里，不再在底部条重复（D2 修 PM 验收）
2. 原始模式且有没看过的 Agent 回复（不含示例方案、「待核对」面板开着时不出）→ 淡紫「Agent 处理了 2 条答复」+「看看」（打开待核对）
3. 原始模式且有待回答的问题卡（`questionStatus` 为 open，含 Agent 追问）→ 柠檬「还有 3 处读图没把握」（已答过的加「，已答 1 条」）+「逐个核对」（打开第一张待回答的卡）
4. 原始模式没有待回答、但有已答等 Agent 处理的 → 淡紫「答好了 2 条，交给 Agent 按答复改」+「把答复交给 Agent」（打开交给 Agent，附上答复）
5. 原始模式都处理完 → 薄荷「原始结构核对完了」+「开始试改造」
6. 改造模式没改动 → 「选一面墙或一扇门窗，试着改它」（无按钮）
7. 改造模式有改动 → 「已改 5 处」+「看对比」
8. 对比模式 → 淡紫「拆 2 · 加 1 · 改 1」+「交给 Agent 出说明」

问题卡打开时隐藏（问题卡自己有「下一个」）；画墙 / 门窗等工具激活且没选中时也隐藏（顶部有工具提示）。

**「交给 Agent」入口只出一个主的**：有选中 → 检查器操作行；没选中 → 底部条（规则 8，对比态；规则 4，把答复交给 Agent）；顶栏右上角始终有一个次要的玻璃圆钮。改造清单卡在桌面上不再放「看对比 / 交给 Agent」按钮（底部条已有），手机上清单抽屉打开时底部条隐藏，所以手机抽屉里保留这两个按钮。

## 9. 问题卡（可信）

- 每个构件的检查器第一行是把握程度：看到（实心点、灰）/ 推断（半实心、柠檬浅）/ 不知道（虚线圈、柠檬深），后面是一句依据原文「黑色实心，比隔墙厚，推测承重」和确认人。
- 问题针钉在 `bbox` 中心（参考图 1 的热点），待答的带呼吸光；已答等 Agent 处理的是淡紫小针（沙漏）；已处理的不再占画布（列表里看，展开那张卡时才出现）。
- 问题卡（参考图 1 的摄像头缩略图卡）：上面是**底图局部**（按问题框外扩取景，柠檬虚线框标出问的位置），下面是问题、把握程度、「问的是 客厅横梁 →」（点了选中那个构件）、选项胶囊（点即答）、自由回答输入框、「先跳过 / 下一个 1/3」。
- 打开问题卡时自动打开把握程度描边，用户能看到「还有哪些是猜的」。

### 9.1 问题卡状态（设计-待核对状态-1030）

问题卡有三种状态（core `questionStatus`；没有 `status` 的老文件按答复和回复推）：待回答 open → 已答，等 Agent 处理 answered → 已处理 resolved。**淡紫 = Agent**：等 Agent 处理、Agent 的回复、交给 Agent 都是淡紫；薄荷是用户自己的答复；柠檬仍是「要你动手」。

- **待核对面板**分三组：待回答（缩略图卡，Agent 追问的在问题下面接一行淡紫「Agent 追问：…」）；等 Agent 处理 n（组头右侧淡紫小胶囊「把答复交给 Agent」，条数在组头；底部条、单张卡上的按钮同名，手册和用法说明都用这个叫法）；已处理 n（问题一行、Agent 回复一行 + 处理结果小标签：已按答复修改 / 已确认，没改 / 按推断保留 / 已记下 / 已撤回；没看过的回复右侧一个淡紫点）。标题计数只数待回答；副标题：有待回答 →「Agent 读图时拿不准的地方」，否则有等处理 →「答好了，交给 Agent 按答复改」，否则「答复都处理完了」。原始模式下，只要还有待回答或等处理的卡，右侧默认摆出待核对。
- **展开的卡**是一条时间线：问题 →（之前几轮，可展开）→ 你的答复（薄荷）→ Agent 的回复（淡紫，带处理结果标签；`reply.changed` 里的构件做成小胶囊，点了在图上选中）。操作按状态：待回答 = 选项 + 输入框 + 跳过 / 下一个；等处理 =「把答复交给 Agent」（墨色，交的是全部已答的卡）+「改答复」+ 右侧淡文字「我自己改好了」（写 `reply.by = 业主`、`outcome = noted`）；已处理 =「有异议，再答一次」（提交后回到等处理，上一轮进 `log`）。第一次答完跳到下一张待回答的；改答复、再答一次留在这张。
- **顶栏「待核对」圆钮**角标：有待回答 → 柠檬数字；只剩等处理 → 淡紫数字。
- **交给 Agent**：有等处理的卡时，弹层里多一行「附上待核对答复（n 条）」开关（从「把答复交给 Agent」进来时打开，普通「交给 Agent」默认关）。服务模式：说明「答复已存回方案文件」，复制前有未保存改动先 `saveServed()`，存不进去就按文件模式写；其余模式：说明「答复在这段文字里，Agent 会照着写进方案文件」。答复以外还有没导出的改动（和载入 / 存回 / 导出时的 `cleanBase` 比，问题卡和 meta 不算）时，交接文字里多一句请用户先导出。
- **Agent 回复看过没**（`src/ui/replies.ts`）：只记在本机 localStorage（`tyh.seenReplies`，按方案文件名或标题分开，指纹 = 问题 id + 回复日期 + 回复文字），不写进方案文件。打开那张卡、或「待核对」面板收起时记为看过；用户自己标的「我自己改好了」不算回复。

## 10. 交给 Agent

选中（可多选）→ `A` → 弹层：带上的构件（可删）→ 一句话（三个例句可点）→ 预览将复制的文字（手机默认收起）→ 「复制给 Agent ⌘↵」→ 按钮变薄荷「已复制」+「粘贴到你的 Agent 对话里就行」。没选构件也能交（整个方案）。文字由 core `agentHandoff` 生成（方案文件路径取 `meta.planFile`；本地服务模式下是方案目录的绝对路径 + 文件名）。浏览器不让写剪贴板时（`file://`、无权限）展开预览并选中全文，提示「按 ⌘C 复制」。

## 11. 空状态

首次打开（没有本地保存、没有 `?plan=`、没有演示参数）显示空状态。一张大玻璃卡、虚线内框：「把户型图 / **拖到这里**」+ 一句隐私说明 + 两个入口（户型图 → 先当底图再让 Agent 读；方案文件 → 直接打开）+ 三步流程 + 「还没有图？打开示例方案」（载入 `mock.ts` 的虚构两室，标题「示例 · 虚构两室」写明示例）+「新建空方案」。两个入口分别打开图片 / JSON 选择框；拖入同样处理（JSON 走 core `parsePlanText`，旧格式自动转换，有近似时顶部轻提示「已转换旧格式方案：有 N 处近似」+「查看」打开转换报告卡）。拖文件进窗口时内框和整屏变薄荷。没画装饰插图——试过一组等轴白模块，被卡片裁切后像没对齐，按「画不好就不画」去掉了。

### 12.1 装修态 3D（D5：白模加平涂色，本人 10-29 定走 A + D）

- **平涂（默认）/ 白模**：3D 工具栏一格（`look-clay`）。平涂 = 墙面、地面按 core `resolveFinish` / `resolveSurfaces` 的材料铺平涂色；柜体、造型按各自材料色；家具白盒（地毯铺风格的地毯色）；电视深色。白模 = 纯白，和结构态白模同一套材质。两种都能导出 PNG（文件名带「装修平涂 / 装修白模」，剖切时再带「剖切」）。画中画在装修态里也是这一套。
- **3D 样色 `tone3d`**（`src/three/decor3d.ts`）：OKLCH 明度往纸白拉 30%（夹在 0.80–0.965），彩度 ×0.8 且 **上限 0.06**。比平面 `planTone`（拉 50%、彩度 ≤ 0.033）浓一档：3D 有光影会再压暗一点，屏幕上读起来和平面差不多轻；上限仍不到语义粉彩（0.12+）的一半，薄荷选中、柠檬提醒照样跳出来。想更「真」改 `TONE3D.Cmax`，想更「白模」改 `TONE3D.pull`。
- **墙面皮（D6 起）**：平涂的墙面改用 core `wallSkins`——每面墙每一侧一整张连续的面（门洞扣轮廓、窗洞留孔、按材料分片、片与片零缝、跨共线墙段合并），贴在墙面外 1.5 mm；不贴房间的那侧（外墙外侧）不铺，留白模白。门洞上方、两侧不再一段一段地接缝。下面「墙面上色」只剩墙顶和洞口侧壁在用。
- **墙面上色**：合并后的墙体几何每个竖直三角形查它落在哪面墙面上（法向 + 离墙面半厚），上那一面的整面材料色（顶点色）；不朝房间的外侧留白模白。一段 / 到某个高度的覆盖、跨房间另一段的材料，按 `resolveSurfaces` 的片贴一层 1.5 mm 的皮。墙顶按墙类型的浅灰（`FLAT_TOP`，外墙 `#b9bdc4` / 承重 `#aeb3bb` / 隔墙 `#d9dce0`，比结构态的墙顶浅两档），俯视读得出外墙 / 隔墙但不抢材料。
- **玻璃**：平涂下用白模那种极淡的冷白半透明（结构态的天青在大面积玻璃隔断上太抢）。
- **程序线**：只有地面——木地板错缝、砖缝，比底色暗 ΔL 0.045、透明度 0.55，真实尺寸；墙面不加纹理。不铺照片纹理。
- **棱线**：平涂下墙沿用结构态的极淡棱线（墨 9%），柜体单独深一档（墨 20%），门缝、抽屉缝读得出来；白模下不画线。
- **平视**：平涂和白模一样，朝相机的外墙直接不画（不留半透明幽灵墙）。装修态里层高胶囊不出（工具栏没有「顶面」开关）。
- **只藏有嵌入的墙**：core `buildDecorSolids().hideWallIds` 列出的墙用替换实体（墙体真的变薄），其余墙照常按墙分组上色、对比态退灰、平视剖切、点选高亮；替换墙的选中 / 悬停高亮也用替换实体。
- **1.1 m 水平剖切**（`section-3d`，白模和平涂下都能开）：渲染器全局剪裁平面切在「当前楼层标高 + 1.1 m」，切面用 core `sectionAt`（结构用 `decorWallSolids`，墙上已扣掉嵌入的凹槽）画实心盖子：墙浅墨 `#7d838c`、玻璃浅天青、柜体 / 造型浅杏 `#d9c6a6`、家具白，盖子描一圈墨 55% 的边。打开时相机仰角自动抬到 ≥ 62°（偏俯视）。
- **对着这面墙看**（探针 P1–P3 改用它，不再手调）：水平方向 = 墙面法向；仰角取「从构件那一块墙面（沿墙 5 个点 × 3 个高度）往相机看，越得过前面的墙顶和梁」的最小角 + 4°；正对被梁挡住时水平方向偏 15° / 25° / 35° / 45° 再试，都挡就取挡得最少的。P2 看的是洞里的电视（梁压在背景墙中线上，看整块背景墙一定挡）。
- **Agent 待确认的结构提议**：装修态只留一圈边线（D6，不铺淡紫体块、没有热点），导出 PNG 时藏掉。
- **弧墙门窗（D6，接 core C6）**：弧墙上的每扇按 core footprint 挤出一整片弧面玻璃 / 门扇；框只在洞口两端和扇间交界画竖框、上下沿弧各一条横框（平开门不画底框）。直墙门窗画法不变。
- **透明背景导出**：窗户默认实心浅灰（`#dfe2e6`，不透明），导出框里可以换回「半透明」。

### 12.2 改造清单导出 ·「装修想法」房间页（`src/ui/export/decor.ts`）

## 12.5 连接方案文件（`src/ui/file-link.ts`，`actions.ts`）

网页拿不到文件路径，所以记 File System Access 的文件句柄（存 IndexedDB）。Chrome、Edge 打开或拖入 `.json` 时连接（`source.kind = 'linked'`，`etag` = 修改时间 + 大小）；其他浏览器走隐藏 input，只读一次。和服务模式共用「外部版本来了怎么办」（`takeRevision`）：坏的不载入，没有未保存改动直接载入，有就先问。顶栏状态、保存按钮、⌘S、交接前先存回都和服务模式一样（`isConnected`、`saveToFile`）；写回前核对 `etag`，文件被改过就不写，弹「载入 / 知道了」。启动优先级：`?plan=` > 演示参数 > 连接的文件 > 自动保存 > 空状态；自动保存记 `dirty`，有没写回的改动时恢复改动、不读文件。权限没了（关过浏览器）弹「重新连接」，因为确认必须由用户点一下。打开别的方案（`source` 变了且不是 linked）就断开并忘掉句柄。

## 13. 网页 Chat 流程（T2：粘贴方案 / 复制问题给 Chat / 复制方案给 Chat）

没有 Agent 的人用网页 Chat 读户型图：Chat 输出方案 JSON → 粘进工具校验、看 3D → 把问题复制回 Chat → Chat 改完再输出整段。逻辑在 `src/ui/chat-text.ts`（纯函数，有 vitest），状态和动作在 `src/ui/chat.ts`，对话框 `src/ui/panels/ChatSheet.tsx`。

- **入口**：空状态第三块入口（两块大入口下面一条通栏，淡紫图标）；文件菜单「打开方案」下面「粘贴方案」；文件菜单镜像组上面一组「复制问题给 Chat」「复制方案给 Chat」。手机同一个文件菜单。为什么放文件菜单：两件事都是「整份方案进出工具」，和打开 / 导出同一类；问题卡面板只管读图问题，放进去会让人以为只复制问题卡。
- **对话框**：外形同「交给 Agent」（桌面居中弹层，手机底部抽屉），Chat 相关和 Agent 一样用淡紫。粘贴框粘进来立即解析（`onPaste`），手打的点「载入方案」或 ⌘↵。结果框：柠檬 = 要你动手（截断、格式 / 几何错误、找不到 JSON），墨 = 二次确认（替换有未保存改动的方案）。错误只列前 4 条，全文在「复制问题给 Chat」页。
- **找 JSON**：去掉 ``` / ~~~ 和前后说明；多个代码块取最大的；没有代码块在整段里找最大的 `{…}`；括号没配完 = 截断（报从 `{` 起第 N 个字符）；`//` 注释和结尾多余逗号自动去掉；外层括号对不上时不拿里面配得平的小对象冒充方案；解析出空方案（不是方案的 JSON）不载入。之后走 core `parsePlanText` + `loadError`：有错误不替换当前方案。
- **第二轮底图**：当前底图是导入过的图片（data URL）、新方案里只是文件名（或没写底图）→ 图片沿用当前的，比例 / 原点 / 透明度 / 镜像用新方案里 Chat 估的，提示「…，底图沿用当前的图片」。当前没有图片时提示「方案里引用了底图 xxx.png，点这里导入户型图」，按钮走 `relinkUnderlay`（只换 src，保留比例和原点；「导入户型图」菜单项会按平面外框重算比例，不用它）。
- **底图文件名**：data URL 里没有文件名，store 的 `underlayNames` 记住导入时的文件名（随自动保存存下）；「复制方案给 Chat」把 data URL 换回这个文件名，没有记录时写 `户型图.png`。
- **复制**：`navigator.clipboard` → `execCommand('copy')` → 都不行时对话框里弹只读文本框、聚焦全选，提示按 ⌘C。复制问题页有一个可选的「还想告诉 Chat 什么？」。
- **3D 导出图片**加「画幅：当前画面 / 16:9」：16:9 时取景框按模型外接框补成 16:9（可以超出屏幕，手机竖屏也完整），输出长边 ≥ 1920 的 16:9 PNG，文件名带 `-16x9`。
- **简版方案（D7，接 core C7 `src/core/simple.ts`）**：网页 Chat 推理一般的模型写不对完整 v3，改让它输出只有房间和门的简版，core 自动生成墙、门洞和问题卡。粘贴分三种：
  1. **简版能转换**：照常载入（有未保存改动照旧先确认），提示「已载入简版方案：N 面墙、N 个门洞、N 个房间（墙和门洞是自动生成的），没有窗户」。打开简版文件同样处理，不弹「已转换旧格式」。
  2. **简版有阻断错误**：柠檬结果框「简版方案有错误，没有载入」，列 core 的错误原文（已经是简版路径，比如 `rooms[0]（主卧）.poly：至少要 3 个点`），「复制问题给 Chat」的文字第一行「请按下面的问题修改简版方案……不要改用别的格式。」，后面是问题和 core 的 `SIMPLE_RULES` / `SIMPLE_TEMPLATE`（界面不另抄一份）。
  3. **格式根本不对**（core `diagnoseShape(raw).wrong`，在格式 / 几何错误之前判断）：不载入、不列字段错误，结果框「格式不对，工具读不了」+ 最多 4 条短原因，主按钮「复制简版模板给 Chat」复制 `simpleFormatChatText(reasons)`；复制问题页的预览、打开方案文件 / 服务模式读到这种文件时提示条里的「复制问题给 Chat」都走这一段。合法 v3、能转出墙的旧格式不受影响；「rooms 有、walls 空」的 v3 在这里拦下（打开文件也拦）。
  - **根本不是方案**（B8，core `isNotPlan`，在第 3 种之前判断）：没有方案格式标记、没有旧版 layout，本身和套的一层里都没有 walls / rooms / doors 数组的 JSON，或者自己标着别的 `floorplan-*` 格式（see-your-home 的 `*.camera.json`、stats、validate 结果之类）。这是选错了文件，不是谁写错了格式，不给简版模板：粘贴走「这段 JSON 里没有墙、房间这些构件，不像是方案」；打开文件 / 服务模式（含轮询）提示条「这不是方案文件（文件名），没有载入。请选 交付/方案.json，或从工具导出的方案 JSON」，主按钮「选方案文件」，没有「复制问题给 Chat」。
  - **说明条**（`panels/SimpleNote.tsx` 的 `SimpleBanner`）：载入简版后在顶栏下方居中展开（桌面宽 ≤ 620，手机全宽），弹层玻璃 + 一圈柠檬发丝线 + 左上一片淡柠檬光 + 柠檬图标盘——柠檬是「没把握 / 要你动手」，墙和门洞是猜的，正好是这个意思；**不用珊瑚红**（留给「拆」）。标题「简版方案」+「墙和门洞自动生成」「没有窗户」两枚小标签（手机省掉），正文三行照任务书原文；右上「怎么补窗」（展开一行实际入口：左侧 / 底部工具栏「门窗」→「窗」→ 在墙上点，带「开始加窗」直接进门窗工具、类型选窗）和「收起」。带 `data-float`，适配会让开它；展开、收起、展开「怎么补窗」后各重新适配一次。画墙 / 门窗等工具激活时（顶部是工具提示）和装修态里不出，标记还在。
  - **「简版」标记**（`SimpleMark`）：只要 `isSimpleDerived(base)`（`meta.source === 'floorplan-simple'`）就在——存盘、刷新、自动保存恢复后都在。桌面在方案胶囊右边；手机在第二行三态分段左边（第一行方案胶囊已经很挤，放那里会把方案名挤没）。说明条展开时标记铺柠檬（像按下去的开关），收起时玻璃底 + 柠檬图标盘；点它展开 / 收起。新粘贴、新打开一份简版时说明条重新展开；刷新、打开存过的完整 v3 时保持收起。
  - 待核对列表的副标题对简版写「简版自动生成时拿不准的地方」；没有位置的问题卡（`simple-windows`）打开时问题卡回到画面中间（不沿用上一张的锚点）。手机上的长提示换行显示，不出屏。
