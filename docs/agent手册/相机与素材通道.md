# 5 附 相机与生图素材通道

**什么时候读**：要挑房间平视机位、自定义相机、复现某张图，或者用户要深度图、线稿、分割、门窗遮罩去生图时。命令的通用用法、参数表和耗时见 [命令.md](命令.md)。

所有相机输入、输出长度为 **mm**。三维坐标为右手系 `[x, y, z]`：x 对应平面 x，y 向上，z 对应平面 y。角度为度，`fov` 是竖向视角。GLB 按 glTF 标准使用米。

先运行 `node "$SKILL/scripts/plan-cli.mjs" cameras "$WORK/交付/方案.json"`。清单按楼层列出 `iso-sw`、`iso-ne`、`iso-se`、`iso-nw`、`top`，以及 `room:房间id` 和 `room:房间id:墙id`，默认每个机位一行，包含 id、楼层和中文说明；`--json` 输出完整 JSON，`--all` 额外列朝墙变体。`--state renovated` 列改造后的机位，`--level L2` 筛选二层（输入必须包含 L2，不存在的楼层会报错）。方向名按图纸轴，不按 north 旋转。四个斜视从南或北偏 24°、仰角 50°（如 `iso-sw` 从南偏西看），正交投影。

```sh
node "$SKILL/scripts/plan-cli.mjs" render "$WORK/交付/方案.json" 图 --camera room:r-living --size 2400x1600
node "$SKILL/scripts/plan-cli.mjs" render "$WORK/交付/方案.json" 图 --camera 'pos=2000,1450,1000;target=2000,1450,4000;fov=75'
node "$SKILL/scripts/plan-cli.mjs" render "$WORK/交付/复式方案.json" 图 --camera top --level L2 --section 1200 --transparent
node "$SKILL/scripts/plan-cli.mjs" render "$WORK/交付/方案.json" 改造图 --camera iso-sw --state renovated
node "$SKILL/scripts/plan-cli.mjs" render "$WORK/交付/方案.json" "$WORK/交付/生图素材/客厅" --camera room:r-living --passes clay,depth,lines,seg,openings
```

**怎么挑平视**：先用 `room:房间id` 默认机位；用户说了想看什么（如「客厅电视那边」），就运行 `cameras … --all`，按说明里的「看向哪面墙」「画面里有哪扇门窗」挑 `room:房间id:墙id`，不要把算法推测的整面实墙当成已知电视位置。改造后重新运行 `cameras … --state renovated`（需要时加 `--all`）再挑，并用相同 state 渲染；旧相机的位置或朝向不一定适合合并后的房间。

房间机位的眼高是本房间地面以上 1450 mm，竖向 fov 75°（3:2 画幅横向约 97°）。自动选位按拍室内照片的习惯：

- 站位先找离墙面和房间边界至少 900 mm、不在柱和管井占地里、离平开门铰链超过「门宽 + 200 mm」的点；找不到再依次放宽到 600、450、300、180 mm。
- 每个站位和朝向先用 48×32 的小图试拍打分，普通得分前 6 名和有门窗的前 6 名再用 96×64 在三个俯仰角复评；粗细采样不一致时继续检查其他候选。默认机位只要有可见门窗的候选，就必须从这些候选中挑（复评至少 12 个可见像素，粗评门槛 3 个像素）；有单个门窗占画面至少 1% 的候选时再优先选它，避免只有边缘一小条门；朝墙变体遵从指定朝向。加分：看得到的本房间地面面积、门窗、这间最长的一段整面实墙（卧室的床头墙、客厅的电视墙一般就是它）。减分：画面中间 1500 mm 内被挡、1000 mm 内有墙贴脸、天花超过画面约 1/4、地面太少、门扇入画、镜头下俯。
- 镜头最多下俯 6°，竖线基本不歪。
- 客厅（房间名含「客」「起居」或 living）偏好与主窗、阳台墙垂直的整面实墙，但默认候选也包含其他相邻墙的朝向；可见门窗的要求优先于电视墙偏好。
- 朝墙变体 `room:房间id:墙id` 在可站的点里挑一个，正对那面墙。
- 每个机位的说明写：靠哪面墙站、看向哪面墙、画面里有哪些门窗。可站位置的离墙距离只能放宽到 600 mm 以下时，说明末尾加「房间窄，平视画面有限」。可见地面占比低只参与构图打分，不把扩大或凹形房间误称为窄房。

不计面积（`counted:false`）、面积小于 1.5 m²、或地面抬高超过 300 mm 的房间（如飘窗台）没有平视机位，`room:` 直接指定也会被拒绝；要看就用自定义坐标。开敞阳台保留机位，说明里写「开敞阳台，平视多半是天空」。

没有任何可站的点时，`render` 报错，需要给自定义坐标，不会把相机塞进墙；`cameras` 清单略过这间。平视自动补所选层所有房间的天花；指定 section 时不补。

### 示例里看过的机位

Skill 自带示例 `$SKILL/assets/example/`（只有 plan.json、input.png）的每个房间都出过平视，逐张看过。结论（不列具体朝向和门窗，免得读示例图时先看到答案）：

- 客厅、主卧的默认机位构图好看，客厅默认会对着一面整墙，门窗在两侧；
- 朝墙变体正对窗时也好看；次卧、厨房可用，构图偏平；
- 不到 2 米宽的卫生间只拍到门和两侧墙，看俯视；
- 开敞阳台平视一半是天空，看斜视；
- 飘窗台这类不能站人的房间没有机位，看它所在房间的机位。

`--level` 选择单层，仍保留绝对楼层标高；默认斜视展示所有层，room 相机自动选房间所在层。`--section` 是相对所选楼层楼面的剖切高度 mm，所有实体截断并封盖；top 默认 1200 mm。`--state renovated` 仅重放 confirmed，保留 pending 为提议。

批量渲染可重复 `--camera`，同次运行共享结构网格和房间场景（不同楼层 / 剖切高度分别缓存）：

```sh
node "$SKILL/scripts/plan-cli.mjs" render "$SKILL/assets/example/plan.json" 图 --camera room:r-living --camera room:r-master --camera iso-sw
node "$SKILL/scripts/plan-cli.mjs" cameras "$SKILL/assets/example/plan.json" --json > cameras.json
node "$SKILL/scripts/plan-cli.mjs" render "$SKILL/assets/example/plan.json" 图 --cameras cameras.json
```

`--cameras` 接受非空 JSON 数组：机位 id 字符串、相机文件路径、相机对象，或 cameras --json 的完整列表。同名机位在同一批次内会追加楼层和序号以避免覆盖。文件路径相对当前命令目录；每个相机文件保留自己的尺寸、状态和通道，显式 CLI 参数统一覆盖。进度写入 stderr。输出机位名中的冒号等字符替换为下划线，例如 `room:r-master:w-n` → `room_r-master_w-n-white.png`。

耗时见 [命令.md](命令.md) 5.6。

通道后缀接在白模文件去掉 `.png` 的完整名称后，例如 `room_r-living-white.depth-inv.png`、`room_r-living-white.lines.png`。

每个视角输出 `<机位>-white.png`（或 transparent），并输出同名 `.camera.json`；只指定辅助 passes 时可以不出白模。相机文件含 pos/target/up、投影类型、内外参、画幅、状态、楼层、section、透明开关及通道清单。直接把文件传给 `--camera` 可原样复现；显式命令行参数覆盖文件中的渲染选项。自定义简版相机 JSON 至少包含 `projection:"perspective"`、pos、target、fov（默认 75），正交相机另需 span（垂直画幅跨度 mm）。

矩阵为列主序，输入世界坐标 mm；相机视线是相机空间 -Z。透视 intrinsics.fx/fy 为像素焦距；正交为 px/mm。图像原点在左上，bbox_xyxy 为可见像素的闭区间。

| 通道 | 同名后缀与约定 |
| --- | --- |
| clay | 主 PNG；2× 超采样。颜色、光照集中在 RENDER_STYLE：主光跟着相机从左前上方来，斜视和俯视带软阴影，房间平视用更平的室内光、不打阴影 |
| depth | `.depth-inv.png`（亦存为 `.depth.png`）：1/z 单张 min–max 归一化，近白远黑；背景 0，恒深度前景 255 |
| depth | `.depth16.png`：16 位灰度，线性相机 z 毫米，0 无几何，65535 饱和；camera.depth 标记饱和和实际 min/max。`.raw-depthmm.png` 用 R×256+G 编码同一数值，便于沿用原型解码 |
| lines | `.lines.png` 白底黑线、`.lines-inv.png` 黑底白线；根据可见面的法线和几何平面断层取边，忽略共面分段及三角形内边，不按构件 id 画缝 |
| seg | `.seg-ade20k.png` 与 `.seg.png`：墙 120,120,120；地 80,50,50；顶 120,120,80；窗 230,230,230；门 8,255,51；背景 0,0,0；标签不混色 |
| openings | `.opening-001.png` 等：每扇洞口一张二值可见区域遮罩；不可见洞口全黑。`.openings.png` 是 16 位灰度实例编号，0 背景，不沿用原型 R/10 的 25 实例限制 |

相机 `openings` 只列画面里可见的洞口，含 idx/id/name/kind、宽 width_mm、洞底 sill_mm、洞顶 head_mm、visible_px、bbox_xyxy、mask 文件名。`openingMasks` 列全部实例，便于查全黑的遮罩。轮廓和类别在同一几何、相机下生成；门窗遮罩使用厚度增加 20 mm 的洞口体积，仍受场景深度遮挡。白模图里的玻璃画成浅色，透出后面一层（只透一层，不做多层排序），边缘提亮；深度、线稿、分割、遮罩里玻璃仍按实面处理，归 window 类。`--transparent` 只控制背景，玻璃后面什么都没有的地方是半透明。

16 位深度和语义图在每个输出像素的 2×2 样本中取最近可见表面；不混合门窗/墙标签。线稿是屏幕空间可见轮廓，受像素分辨率、阈值和弧墙离散精度影响。不会添加家具、窗帘或材质；生图时把这些图作为结构条件，最终图仍须核对门窗位置。
