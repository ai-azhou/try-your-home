# 5 命令：CLI、辅助脚本、环境

**什么时候读**：第一次运行命令之前（先看 5.1 路径和 5.2 环境）；命令报错、不知道输出什么意思时；想估计一条命令要跑多久时。

CLI 是 `scripts/plan-cli.mjs`（由 app 的 `scripts/plan.ts` 打包，离线运行，只读写本地文件）。相机和素材通道的细节在 [相机与素材通道.md](相机与素材通道.md)。

## 5.1 路径：Skill 目录和工作目录分开

- `$SKILL`：Skill 根目录的**绝对路径**，也就是 SKILL.md 所在的文件夹（例如 `~/.claude/skills/see-your-home`）。只读，不往里写产物。
- `$WORK`：用户的工作目录，放户型图、方案 JSON 和全部产物。
- 命令在 `$WORK` 里执行，脚本写绝对路径，输入输出写 `$WORK` 里的路径：

```sh
SKILL="/绝对路径/see-your-home"
WORK="/用户的/工作目录"
cd "$WORK"
node "$SKILL/scripts/plan-cli.mjs" validate "$WORK/交付/方案.json"
python3 "$SKILL/scripts/overlay.py" "$WORK/户型图.png" "$WORK/交付/方案.json" "$WORK/交付/叠图.png"
```

路径里有空格或中文时整段加引号。Python 脚本用绝对路径运行即可，它们自己找同目录的 `plan_io.py` 和 `plan-cli.mjs`。`render --cameras` 列表里的相机文件路径、`schema` 的输出都相对**当前目录**。

## 5.2 环境检测

| 要用的 | 需要 | 检测命令 |
| --- | --- | --- |
| `plan-cli.mjs` 全部命令、`check-glb.mjs` | Node.js 20 及以上 | `node --version` |
| `overlay.py` | Python 3.12 或 3.14、Pillow，**以及 Node**（它经 CLI 读方案） | `python3 -c "import PIL; print(PIL.__version__)"` |
| `embed_underlay.py` | Python 3、Node（不需要 Pillow） | `python3 --version` |
| `rectify.py`（翻拍校正、翻转图片时） | Python 3、Pillow | `python3 -c "import PIL"` |
| `extract_drawing.py`（可选） | Python 3、Pillow、NumPy | `python3 -c "import PIL, numpy"` |
| `gen_prompt.py`（生图，可选） | Python 3（只用标准库） | `python3 --version` |
| `gen_score.py`（生图，可选） | Python 3、Pillow、NumPy | `python3 -c "import PIL, numpy"` |

一次查完：

```sh
node --version; python3 --version; python3 -c "import PIL; print('Pillow', PIL.__version__)"; python3 -c "import numpy; print('NumPy', numpy.__version__)"
```

支持并实测 Python 3.12、3.14；本轮环境为 Node 24.21.0、Python 3.12.14 / 3.14.7、Pillow 13.0.0、NumPy 2.5.4（macOS arm64）。其他 Python 版本未验证。Python 经 PATH 查找 `node`，可使用带依赖的虚拟环境 Python 配合系统 Node。

**缺了怎么跟用户说**（不替用户装，用户同意了才装）。原话示例：

> 我要用 Python 的 Pillow 把读出来的墙画回你的户型图上，方便你一眼核对读得对不对。你电脑上的 python3 还没有 Pillow。要我帮你装吗？会执行 `python3 -m pip install --user Pillow`，只装这一个包。不装也行，我照样能出白模和图片，只是少了叠图这一步自查，我会在交付里写明。

> 生成 3D 白模需要 Node.js 20 以上，你电脑上没有找到 node。可以从 nodejs.org 下载安装，或者用你习惯的包管理器装。装好告诉我，我再继续；在这之前我只能先把读出来的结构写成方案文件。

- 用户同意后才执行安装命令；用户有虚拟环境或别的 Python，就用他指定的解释器。
- 用户拒绝：缺 Pillow 就跳过叠图，在附录「没做的检查」里写明；缺 NumPy 就不用 `extract_drawing.py`（它只是辅助），生图也没法自动打分，要出效果示意图就请用户逐张对着白模图看；缺 Node 就无法校验、出模型和图，只能交付方案 JSON 草稿并说明没校验过。

## 5.3 CLI 命令

写法：`node "$SKILL/scripts/plan-cli.mjs" <命令> <输入> [输出] [参数]`。输入方案写 `-` 表示从 stdin 读。所有命令：成功退出码 0；任何错误退出码 1，错误信息写 stderr，以「错误：」开头。例外：`validate` 总是在 stdout 输出 JSON；`apply` 在原始结构有效时在 stdout 输出 JSON。方案文件有 schema 错误时，除 validate 外的命令都直接拒绝；原始结构有几何 error 时，apply、export、render、cameras 也直接拒绝（apply 不输出 JSON，只有一行「错误：」）——先把 `validate` 跑通。

| 命令 | 用途 | 输出 | 退出码 |
| --- | --- | --- | --- |
| `validate <方案.json>` | 检查字段形状（schema）和原始结构几何 | stdout JSON：`{"valid":bool,"issues":[{"level","code","message","ref?"}]}` | valid=false 时 1 |
| `stats <方案.json>` | 数量和面积 | stdout JSON：`netArea`（计入房间的净面积 m²）、`grossArea`（含墙外轮廓，上限估算）、`wallArea`、`excludedRooms`、`walls`、`doors`、`windows`、`openings`、`beams`、`rooms`、`roomAreas[]`、`unansweredQuestions`（待回答的问题卡数，含追问的）、`questions`（`{open, answered, resolved}` 三种状态各几张）、`pendingChanges`。`excludedRooms` / `excludedArea` 只在有不计面积的房间（或有 byLevel）时出现；有楼层、柱、管井、楼梯或挑空时另有 `byLevel` 和这四类的数量 | |
| `apply <方案.json>` | 重放**全部**改造记录（含 pending），检查每条和最终结构；不改文件 | stdout JSON：`results[]`（`id`、`ok`、`error?`、`needsConfirm?`、`affected`、`removed`、`warnings?`）和 `issues[]`（带 `changeIds`） | 任一条 ok=false 或最终有 error 时 1。读法见 [改造.md](改造.md) 3.6 |
| `export <方案.json> <输出.glb> [--state original\|renovated] [--level 楼层id]` | 导出 GLB 白模（glTF 2.0，米，Y 朝上） | 写 GLB；stdout `GLB: 路径` | 方案有 error、改造重放失败或改造后结构有 error 时 1，不写文件 |
| `render <方案.json> <输出目录> [参数]` | 软件渲染白模图和素材通道 | 每个机位写 `<机位>-white.png`（或 `-transparent.png`）和同名 `.camera.json`；stdout 每个文件一行 `PNG: 路径`；stderr 进度 `渲染 i/n：机位` | 同 export |
| `cameras <方案.json> [--json] [--all] [--state ...] [--level ...]` | 列机位 | 默认每行 `机位id [楼层] 中文说明`；`--json` 完整 JSON；`--all` 加朝墙变体 | 方案有 error 或楼层不存在时 1 |
| `convert <旧.json> <新.json\|->` | 旧格式（v2、legacy）转 v3，或把 v3 规范化 | 写文件（`-` 写 stdout）；stderr 是转换报告 JSON（counts、approximations、warnings、idMap） | schema 错误或几何 error 时退出码 1，**不写文件**（目标文件保持不变）；空方案不会覆盖有内容的旧文件 |
| `questions <方案.json> [--status open\|answered\|resolved]` | 列问题卡（处理答复前先用它看要处理哪几张） | stdout JSON 数组：`id`、`status`（缺省时推出来的）、`category`、`text`、`targets?`、`options?`、`answer?`、`answeredBy?`、`answeredAt?`、`reply?`、`log?`；不带 bbox 和底图 | |
| `answer <方案.json> <问题id> --text "…" [--by 业主] [--at 日期]` | 用户在对话里直接答时，把原话记进问题卡（status → answered） | **原地改文件**：只改这一张卡，其余原样保留，原子写回，写前自校验；stdout 改后的这张卡（一行 JSON） | 问题不存在、文字为空、写后校验有 error 时 1，不写文件 |
| `resolve <方案.json> <问题id> --outcome <…> --reply "…" [--changed id,id] [--by Agent] [--at 日期]` | 处理完一条答复，写回复（outcome 见 [格式.md](格式.md) 问题一节） | 同 `answer`；status 按 outcome 改（`ask` → open，其余 → resolved） | 状态不对（只有已答的卡能写回复；`withdrawn` 也可用于没答的卡）、`--changed` 里的 id 不存在、写后校验有 error 时 1，不写文件 |
| `schema` | 在**当前目录**写 `schema/plan.schema.json` | 文件 | |
| `decor <方案.json>` | 装修层检查：重挂结果、问题、材料粗估（不算待确认项） | stdout JSON：`items`、`placed`、`issues`、`rehosted`、`materials`、`pendingCount` | 有 error 时 1 |
| `decor-list <方案.json>` | 写装修前查：每间房每面墙的 `wall`、`side`、门窗，家具库，风格，材料，构件类别，已有项 | stdout JSON | 方案有 schema 错误时 1 |
| `decor-edit <方案.json> <补丁.json\|->` | 写装修层，补丁格式见 [装修.md](装修.md) 7.5 | **原地改文件**：只动 `decor`，其余逐字节不变，原子写回；全部操作成功才写。stdout `{ok,applied,issues,items}` | 任一操作失败或校验有 error 时 1，不写文件 |

`render` 的参数：

- `--include-pending`：装修层里待确认的项也画。默认只画已确认的，`.camera.json` 的 `decor` 里记 `pendingHidden`、`includePending`。

| 参数 | 含义 | 缺省 |
| --- | --- | --- |
| `--camera <值>`（可重复） | 预设 `iso-sw` `iso-ne` `iso-se` `iso-nw` `top`；`room:房间id`、`room:房间id:墙id`；`"pos=x,y,z;target=x,y,z;fov=75"`（mm）；或 `.camera.json` 文件 | 不写就出 `--views` 的三张 |
| `--cameras <列表.json>` | 非空 JSON 数组：机位字符串、相机文件路径、相机对象，或 `cameras --json` 的输出 | |
| `--views a,b,c` | 不写 `--camera` 时出哪些预设 | `iso-sw,iso-ne,top` |
| `--state original\|renovated` | renovated 只重放 confirmed 改造 | original |
| `--level <楼层id>` | 只出这一层；楼层不存在报错 | 斜视出全部层，room 机位用房间所在层 |
| `--section <mm>` | 相对所选楼层楼面的剖切高度 | top 是 1200 |
| `--size 宽x高` | 像素；单边不超过 8192，总像素不超过 1600 万 | 2400x1600 |
| `--transparent` | 透明背景 | 白底 |
| `--passes clay,depth,lines,seg,openings` | 输出通道；只写辅助通道时不出白模图 | clay |
| `--no-decor` | 不画装修层（家具、柜体、墙面造型），只出结构 | 有装修层就画：`--state renovated`，或方案里没有 confirmed 改造时 |

输出文件名里，机位 id 的冒号等字符换成下划线：`room:r-master:w-n` → `room_r-master_w-n-white.png`。同一批里重名会追加楼层和序号。

## 5.4 校验错误码

`validate` 的 `issues[].code`，以及 export / render / cameras / apply 报出的同名错误。结构部分都是 error 级（装修层的 `decor-*` 可能是 warn）。

**先 schema 后几何**：读文件时先跑 schema，schema 不过就只报 `schema`，几何检查不跑。所以下表里 `shape`、`id`、`enum`、`plan`、`levels` 这类字段形状问题，从文件读进来时基本都表现为 `schema`，message 带字段路径（如 `格式错误 /walls/0/kind：must be equal to one of the allowed values`、`/levels：must NOT have fewer than 1 items`）；schema 通过后才会看到 `opening-range`、`room-self-intersection` 这些几何错误码。

| code | 意思 | 怎么修 |
| --- | --- | --- |
| `parse` | 不是合法 JSON，或缺 `format` / `version` / 六个必有数组 | 修 JSON 语法；补齐顶层必填字段 |
| `schema` | 字段形状不对。message 里有字段路径，如 `/walls/0/heigth: must NOT have additional properties` | 按路径改：拼错的字段名、缺必填（如问题缺 `text`）、类型不对（长度写成字符串）、数组长度不对（pixelBox 要 4 个数） |
| `shape` | 构件数组不是数组，或数组里有非对象 | 改成数组 / 对象 |
| `id` | 构件缺 id | 补 id |
| `duplicate-id` | id 重复（跨类型也算） | 改成唯一 |
| `enum` | 枚举值不认识（墙类型、洞口类型、certainty、开向、问题分类、改造 op/type/by/status、柱/管井/楼梯类型） | 用 [格式.md](格式.md) 列出的值 |
| `plan` | 标题或层高无效 | `title` 字符串，`ceiling` 正数 mm |
| `levels` | `levels` 是空数组 | 单层就删掉 levels |
| `level` | 楼层名、标高或层高无效 | 补 name、数字 elevation |
| `level-order` | 楼层标高没有按数组顺序严格递增 | 按从低到高排，标高不能相同 |
| `level-reference` | 构件、挑空或 `levelUnderlays` 引用了不存在的楼层 | 改 level 或补楼层 |
| `wall-geometry` | 墙端点无效、长度为 0 或厚度不为正 | 改 a、b、thickness |
| `height` | 墙 height / lowHeight 或房间 ceiling / floorOffset 无效 | 正数 mm（lowHeight 可为 0，floorOffset 可为负） |
| `opening-host` | 洞口的宿主墙不存在或几何无效 | 改 `wall` |
| `opening-range` | `offset + width` 超出墙长，或宽度不为正、offset 为负 | 重量 offset；弧墙按弧长 |
| `opening-head` | 洞顶高过墙的有效高度 | 降 head，或给墙写 height，或改两侧房间层高 |
| `opening-height` | 洞底为负或不低于洞顶 | sill < head |
| `opening-overlap` | 同一面墙上两个洞口重叠 | 改 offset / width |
| `pane` | panes 为空或比例、类型无效 | 每扇 width>0，kind 为 fixed / casement / sliding |
| `room-points` | 房间缺名称或少于 3 个有效顶点 | 补 name、poly |
| `room-self-intersection` | 房间多边形自交、退化或有重复相邻点 | 按边界依次排点，不回绕；末点不重复首点 |
| `beam` | 梁端点、宽度或梁底无效 | 改 a、b、width、bottom |
| `column` | 柱位置、尺寸、旋转无效，或圆柱两个尺寸不等 | 改 center、size、rotation |
| `extra-points` / `extra-polygon` | 管道井、楼梯、挑空的 poly 少于 3 点、退化或自交 | 改 poly |
| `stair-level` / `stair-direction` | 楼梯起止层不存在、相同，或终点层不更高 | 改 level / to |
| `stair-path` / `stair-size` | path 少于两个不重合的点；宽度或踏步数无效 | 改 path、width、steps |
| `change-params` | 改造记录缺 target 或 data | 见 [改造.md](改造.md) 3.2 |
| `underlay` | 底图路径为空，比例、原点、透明度或 visible 无效 | 补齐 src、mmPerPx、origin、opacity（0–100）、visible |
| `underlay-remote` | 底图是远程地址或外部协议 | 改成本地相对路径或 data URL |
| `format` | 内部版本标记不对（正常读文件不会出现） | 确认 `"version":3` |

## 5.5 辅助脚本

| 脚本 | 什么时候用 | 用法与输出 | 依赖 |
| --- | --- | --- | --- |
| `overlay.py` | 每次改完结构都跑，核对读得对不对 | `python3 "$SKILL/scripts/overlay.py" 原图 方案.json 叠图.png [--labels "书房=9.8,客厅=24.5"] [--scale 倍数] [--font 字体路径]`。写叠图 PNG（原图右侧加图例栏）；stdout 逐间面积、和 `--labels` 的偏差（>5% 标出）、问题框警告、洞口越界提示。`--labels` 的键是房间名或 id，找不到房间、重复、面积非正数都会报错。方案必须有 `underlay`（或每层 `levelUnderlays`）的比例和原点；原图用命令参数传入，不读 `underlay.src` 。仅在 CLI 确认方案校验失败时提示「先跑 validate」并保留原因；文件、字体、Node 等错误显示异常类型和真实原因，按报错处理，不要一律归因于方案。缺 Pillow 时给用途说明并退出 2 | Python 3、Pillow、Node |
| `embed_underlay.py` | 交付前最后一步（可选）：把原图以 data URL 写进方案，方案文件自带底图，以后用工具打开能直接显示 | `python3 "$SKILL/scripts/embed_underlay.py" 方案.json 原图 [--level 楼层id]`。**原地改写方案文件**（经 convert 规范化，见 [格式.md](格式.md) 1.9）。有 `levelUnderlays` 时不带 `--level` 写进每一层；没有 underlay 会新建一个比例为 1 的占位，所以先写好 underlay 再嵌入。嵌入后文件会大几十 KB 以上，之后不要把整个文件读进上下文，要看字段用 `python3 -c` 或 jq 取。方案有 error 时它直接失败（Python 报错栈），文件不变 | Python 3、Node |
| `rectify.py` | 翻拍图有透视要校正（[读图.md](读图.md) 2.2）；家和图是镜像的要翻转（2.1） | 校正：`python3 "$SKILL/scripts/rectify.py" 原图 输出图 --points "x,y;x,y;x,y;x,y" --world "X,Y;X,Y;X,Y;X,Y" [--mm-per-px 比例]`，四点绕一圈写、顺序一一对应，比例缺省按四条边估；写输出图和 `输出图.rect.json`，stdout 打印 `mmPerPx` 和 `origin`。翻转：`rectify.py 原图 输出图 --flip-x`（或 `--flip-y`），和校正分两步。不覆盖原图，整张原图都保留、图外补白，输出不带 EXIF。四点共线、顺序交叉、绕行方向相反（多半是镜像）、透视过强时退出码非 0，不写文件 | Python 3、Pillow |
| `extract_drawing.py` | 可选：干净的电子图（横平竖直、墙涂实心黑）想拿像素坐标辅助读图 | `python3 "$SKILL/scripts/extract_drawing.py" 图.png 输出.json`。输出 `{"size":[w,h],"walls":[[x0,y0,x1,y1],...],"thin":[["h",y,x0,x1] 或 ["v",x,y0,y1],...],"gray":[...],"color":{"red":[...],"green":[...]}}`，全是像素；墙矩形会被门窗洞切成碎块。照片、手绘、彩色图不适用。结果只是候选 | Python 3、Pillow、NumPy |
| `gen_prompt.py` | 生图：按相机文件和风格描述写提示词 | 用法、模板和 `--white-only`见 [生图.md](生图.md) 8.5 | Python 3 |
| `gen_score.py` | 生图：给生成结果打结构分、出三联图 | 用法和结果怎么读见 [生图.md](生图.md) 8.6 | Python 3、Pillow、NumPy |
| `check-glb.mjs` | 导出 GLB 后核对文件格式 | `node "$SKILL/scripts/check-glb.mjs" 白模.glb`。stdout 是 Khronos glTF 校验报告 JSON，看 `issues.numErrors`；有 error 退出码 1。离线运行 | Node |

## 5.6 耗时

本机实测（macOS arm64，Node 24.21.0，Skill 自带示例 `assets/example/plan.json`，含 Node 启动和写文件）。耗时随机器、户型大小和通道数变化，只作量级参考。

| 命令 | 耗时 |
| --- | ---: |
| validate / stats / apply / convert / export / check-glb | 各约 0.1–0.2 秒 |
| overlay.py | 约 0.3 秒 |
| embed_underlay.py / extract_drawing.py | 约 0.4 / 0.5 秒 |
| cameras（摘要）/ cameras --all --json | 约 1 / 2 秒 |
| render 缺省三张（2400×1600） | 约 23 秒 |
| render 一个房间平视（2400×1600） | 9–15 秒 |
| render 一个斜视（2400×1600） | 5–6 秒 |
| render 三个机位一次跑（两个平视 + 一个斜视） | 约 36 秒 |
| render 一个平视加全部素材通道 | 约 18 秒 |

房间平视 9.1 秒、斜视 4.8 秒是机器空闲时测的（2026-10-29 O5 轮）；其余数字是同日机器负载较高时测的，偏慢。

- 一次要出多个机位，就在一条 `render` 里重复 `--camera`，共享网格，比分开跑省时间。
- 单条命令可能超过 30 秒：给命令留足超时（至少 120 秒），或放后台跑；进度在 stderr 里，一个机位一行。
- 试构图时先用 `--size 600x400` 出小图看，定了再出 2400×1600。
