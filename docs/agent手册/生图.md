# 8 生图：效果示意图（可选）

**什么时候读**：用户想看「装好大概什么感觉」时——说要效果图、想看某种风格、发来一张喜欢的室内照片。结构没核对完也可以先出，但要告诉用户图跟着结构走，结构改了要重出。

这一步把白模图交给一个能生成图片的模型，换上材质、颜色和光，结构尽量不动。闭源生图模型都不承诺逐像素保结构，所以做法是：按顺序换输入、自动打分、不过就重出，最多重试 2 次，还不过就交给人看。本篇只交付这一档（普通档）。

## 8.1 开始前跟用户说清三件事

1. **出来的是效果示意**，尺寸以平面和立面为准；模型可能改动门窗，出图后会自动检查一遍，检查不了的地方要用户自己看。
2. **图要发给生图服务**。发出去的是白模图、深度图、线稿（用户给了风格照片，还有那张照片），不是户型原图；但它们仍是用户家的结构。用哪家服务、发不发，用户定；可能要付费或消耗次数，也由用户定。
3. **想要什么感觉**：请用户用自己的话说材料和颜色（地面、墙面、天花、柜门，冷暖、明暗、白天还是傍晚），或者发一张喜欢的室内照片。不要替用户定风格，也不要给风格清单让用户挑。用户只说「奶油原木风」这样很短的描述，就原样写入 `--style`，不追问材料和颜色。

用户同意后再往下做。

**谁来出图**：

- 你能调用生图工具（用户接了生图服务的工具或插件）：照 8.4 的顺序自己出、自己打分。
- 环境里没有生图服务：完成下面的素材交付，不需要为了备料安装或接入服务。
  1. 按 8.3 挑机位、出全部通道，放 `交付/生图素材/<房间>/`；按 8.5 生成 `提示词-1.txt` 和带 `--white-only` 的 `提示词-2-只白模.txt`。
  2. 同目录写 `上传顺序.txt`，列实际文件名：图1 白模 `…-white.png` → 图2 深度 `…-white.depth-inv.png` → 图3 线稿 `…-white.lines.png`；有风格照片再作为图4。只能传一张参考图时，只上传白模并用只白模提示词；只白模的风格照片模板则是白模图1、照片图2。画幅与素材一致。
  3. 告诉用户选择支持相应参考图数量的模型，贴对应提示词，把结果存成同目录的 `结果-1.png` 后交回；后续依次用 `结果-2.png`、`结果-3.png`。
  4. 收到结果按 8.6 打分、看三联图，保存 `分数-1.json` 和 `检查/`；不过按 8.4 换输入，最多重试 2 次（总共 3 次）。没有实际生成结果时只能说明素材已备好，不把白模自检分数当成生图分数。
  5. 这也是一次交付，末尾照样写「**下一步你可以**」：上传素材后把结果交回让我检查；说「换个角度」重新备料；用「改改你的家」打开 `交付/方案.json` 自己试改并导出交回（交付篇 6.7）。

## 8.2 按能力挑模型，不写死模型名

| 看模型这项能力 | 怎么用 |
| --- | --- |
| 一次能传几张参考图 | ≥3 张：从 8.4 第 1 步开始。只能传 1 张：跳过第 1 步，直接从第 2 步「只给白模」开始。带风格照片要 ≥2 张；只能传 1 张时风格照片用不上，照片的感觉改用文字写进 `--style` |
| 能不能指定画幅或输出尺寸 | 能：设成和机位相同的比例（8.3 建议 16:9）。不能：照常出，打分脚本会把结果居中裁到机位比例，但画幅不一致本身就容易诱发重新构图，结果要多看一眼 |
| 有没有遮罩重绘、结构控制（深度 / 线稿控制网络）等输入 | 那是保结构档，**还没验证**。可以用，但不要向用户承诺「门窗一定不动」，照样按本篇打分 |

用户指定了模型就用他指定的；用户问哪个好，只讲上面这几项能力和这个模型具备哪几项，不说某个模型一定守得住结构。

## 8.3 出素材

只用**房间平视**机位（透视相机）；斜视、俯视是正交相机，提示词脚本不接受。先看默认机位的小图；如果看不到门窗或只见空墙角、信息量低，先运行 `cameras "$WORK/交付/方案.json" --all` 挑能看见门窗的朝墙变体，再渲染检查，确定后出正式素材。机位按 [相机与素材通道.md](相机与素材通道.md) 挑；改造后的效果用 `--state renovated` 重新列机位、重新渲染。

```sh
node "$SKILL/scripts/plan-cli.mjs" render "$WORK/交付/方案.json" "$WORK/交付/生图素材/客厅" \
  --camera room:r-living --size 1920x1080 --passes clay,depth,lines,seg,openings
```

- `--size 1920x1080`：16:9，和多数生图模型的横图画幅一致。
- 用户在「改改你的家」里摆了家具（方案里有装修层）：加 `--state renovated` 出素材，家具和柜体会作为白盒进白模、深度、线稿，提示词按「家具外轮廓不变」写。没有家具时出的是空房间，`gen_prompt.py` 会改成「按风格配家具、不挡门窗」，模型自己配的家具位置不受控；想控制家具位置，让用户先在工具里摆好再出素材。
- 五个通道都要出：白模、深度、线稿发给模型；线稿、分割、门窗遮罩给 8.6 的打分用。
- 发给模型的三张：`<机位>-white.png`（图1 白模）、`<机位>-white.depth-inv.png`（图2 深度，近白远黑）、`<机位>-white.lines.png`（图3 线稿，白底黑线）。按这个顺序上传，和提示词里的图号对应。

## 8.4 输入配方：按顺序试

| 第几次 | 只有文字风格 | 用户给了风格照片 |
| --- | --- | --- |
| 第 1 次 | 白模 + 深度 + 线稿三张；提示词用「结构参考」模板 | 白模 + 深度 + 线稿 + 风格照片四张；提示词用「风格照片」模板 |
| 打分不过 → 第 2 次 | 只给白模一张；提示词改成只白模版（8.5） | 白模 + 风格照片两张；提示词改成只白模版（8.5） |
| 还不过 → 第 3 次（最后一次） | 前两次里 S 较高的那种输入再出一张 | 去掉照片，只给白模，照片的感觉用文字写进 `--style`，按只白模版出；先告诉用户为什么去掉照片 |

- 每出一张都打分（8.6）。过了就停，不必用满三次。
- 第 3 次还不过：不再重出，把分数最高的那张连同三联图交给用户看，说清自动检查哪里没过。用户想再试，换一个模型从第 1 步重来。
- 打分结论是「白模边缘不足以标定」时，问题在素材不在模型（例如机位正对一面空墙），换机位重出素材，这一次不计入重试。

**为什么这样排**：实验里不同模型适合的输入不一样。有的模型不给结构图时大半整张重新构图，给了白模、深度、线稿三张以后线位几乎逐条对上；另一个模型只给白模就守得住，三张都给反而整张平移缩放、还自己加了衣柜；加风格照片后，有的模型照样守得住结构，有的把整个房间重新画了一遍。先三张、不过退到一张，对哪类模型都适用。每种组合只有两张图，这些只能说明方向。

## 8.5 写提示词：gen_prompt.py

```sh
python3 "$SKILL/scripts/gen_prompt.py" "$WORK/交付/生图素材/客厅/room_r-living-white.camera.json" \
  --style '用户说的材料、颜色和光，原话整理成一两句' \
  [--template 结构参考|风格照片] [--floor-y-mm 0] -o "$WORK/交付/生图素材/客厅/提示词-1.txt"
```

- 只用 Python 标准库，不联网。缺省模板是「结构参考」；带风格照片用 `--template 风格照片`，照片作为最后一张图上传。
- `--style` 写用户说的材料清单。用户只给了照片、没说材料：写「整体配色、材质和光线照图4 的感觉」，并在 8.7 提醒颜色会被放大。
- 多层户型必须传 `--floor-y-mm`：该层 `elevation`，房间有 `floorOffset` 时再加上它；不传时眼高会按首层算错。
- 脚本从相机文件读视角、站位说明和画面里看得到的门窗（横向百分比、宽高、洞底洞顶），写进「画面里有什么」和「不能动的」。两份模板都写明不加窗帘、百叶、纱帘、帘杆——实验里这句有用，不要删。
- 打开生成的文本看一眼：门窗清单要和白模图上看到的一致。

**只白模版**（8.4 第 2、3 次）：直接加 `--white-only`，无需手工改提示词。

```sh
python3 "$SKILL/scripts/gen_prompt.py" "$WORK/交付/生图素材/客厅/room_r-living-white.camera.json" \
  --style '奶油原木风' --white-only -o "$WORK/交付/生图素材/客厅/提示词-2-只白模.txt"
```

结构参考模板只上传白模图1；搭配 `--template 风格照片` 时上传白模图1、风格照片图2，`--style` 若引用照片也写图2。第 3 次去掉照片时，用 `--template 结构参考 --white-only`，将照片感觉用文字写入 `--style`。

## 8.6 打分：gen_score.py

```sh
python3 "$SKILL/scripts/gen_score.py" "$WORK/交付/生图素材/客厅/结果-1.png" \
  --camera "$WORK/交付/生图素材/客厅/room_r-living-white.camera.json" \
  --triptych-dir "$WORK/交付/生图素材/客厅/检查" -o "$WORK/交付/生图素材/客厅/分数-1.json" [--style-photo 风格照片.jpg]
```

- 依赖 NumPy 和 Pillow（命令 5.2），不联网。白模、线稿、分割、门窗遮罩按相机文件的同名前缀自动找，所以 8.3 的五个通道要在同一目录。一次可以传多张结果。
- 结果画幅和机位不一样时会居中裁切，`crop_note` 里写明。

读 `images[]` 里每张的这几项：

| 字段 | 意思 |
| --- | --- |
| `pass` | 过关：S ≥ 0.6，而且每扇看得到的门窗分都 ≥ 0.6 |
| `S` | 结构边缘和白模的吻合度，白模自己算 1；不是概率，可以低于 0 或高于 1 |
| `S*` | 允许整张缩放、平移对齐后的同一指标，只用来解释是不是取景挪了，过关仍看 S |
| `opening_score`、`openings` | 门窗框线保留率，取最差的一扇；`openings` 里逐扇列出 |
| `conclusion` | 白话结论，见下表 |
| `triptych` | 三联图文件名：左输入白模，中结果，右红绿边缘叠图（绿是对上的线，红是没对上的） |
| `style` | 给了 `--style-photo` 才有：墙、地主色和照片的色差，只描述配色，不参与过关 |

| conclusion | 怎么处理 |
| --- | --- |
| 结构边缘检查过关，门窗语义和最终效果仍请人工看 | 打开三联图自己看一遍（见下），没问题就交付 |
| 整张重新构图，建议重出 | 按 8.4 换下一种输入重出 |
| 整张取景可能发生平移缩放，建议重出 | 结构大致还在、取景挪了。按 8.4 重出；重试用完时可以交给用户，说明「取景和白模有偏移」 |
| 窗户位置可能被改，请人工看 | 打开三联图，看 `openings` 里低于 0.6 的那几扇：真的少了、挪了、变成柜门或墙板，就当不过，按 8.4 重出；看下来没变（例如只是窗外很亮、框线淡），可以交付，并告诉用户哪扇窗要留意 |
| 白模边缘不足以标定，请人工核对素材 | 素材问题，见 8.4 末条，换机位，不计重试 |

**分数看不出来的，你要自己看三联图**：窗被画成柜门、墙板或装饰画；加了窗帘、百叶；加了家具挡住门窗；窗外被画成墙。有这些就算不过，按 8.4 重出，说明里写上原因。

## 8.7 用户给了风格照片

先跟用户说两句：

- 照片只取氛围，具体颜色以材料清单为准。请他补一句地面、墙面大概要什么颜色和材料，写进 `--style`。
- 照片里的拱门、窗、构图不会被照搬（实验里一次也没出现），但颜色常被放大，比如点缀色被刷满整面墙。出图后颜色不对，就在 `--style` 里写明「某某色只用在点缀上，墙面还是浅色」再出。

照片也会发给生图服务；照片是别人家的实拍时，提醒用户注意别人的隐私。

## 8.8 交付口径

- 图放 `交付/效果示意/`，文件名写明房间、风格和「效果示意」，如 `客厅-奶油原木-效果示意.png`。每张旁边放同名三联图或在说明里列出分数。
- 说明里每张图都写「效果示意，尺寸以平面和立面为准」；想把这句印在图上，用 Pillow 在图下方加一条白边写字，不要盖住画面。
- 说清：用的哪种输入（第几次过的）、自动检查结果、还要用户自己看哪几处（例如「左边那扇窗请对着白模图看一眼」）。
- 结构改了（原始或改造）以后，旧的效果示意图过期，按 [交付.md](交付.md) 6.1 的思路判断要不要重出，不要把旧图当新结构的效果。

| 不说 | 改说 |
| --- | --- |
| 这就是你家装好的样子 | 这是效果示意，帮你找感觉；尺寸以平面和立面为准 |
| 门窗位置都没变 | 自动检查过关了，门窗是不是还像门窗，请你对着白模图再看一眼 |
| 这个颜色 / 材料最适合你家 | 按你说的「……」出的，想换就告诉我 |

需要时可以告诉用户：这套做法的实验记录（提示词全文、输入、产图、分数）公开在 see-your-home 仓库的 `evidence/generation/`，每种组合只有两张图，只能看方向。你不必读它。

## 8.9 还没验证的

- **保结构档**：遮罩重绘（只重画墙地顶、门窗区域锁住）、本地模型加结构控制。实验里本地模型线位全对，但把门窗画成了墙板、柜门，自动打分看不出来。这一档还没验证，不交付；用户问起就照实说。
- 打分只看边缘和门窗框线，认不出「窗还是不是窗」；风格色差只描述墙、地主色。
