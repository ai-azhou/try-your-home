# 7 装修

**什么时候读**：交接文字的模式是「装修」；用户要摆家具、挂电视、做柜子、做背景墙、换墙面地面材料、换风格；用户给了一张家具或家电的图，想放进家里。

用户对你说一句话，你把它写进方案的装修层 `decor`，用户在「改改你的家」里马上能看到，也能让你出效果图。

## 7.1 先记住这几条

- **只动 `decor`**：装修直接存当前状态，不写进结构 `changes`。要改墙、开洞，按 [改造.md](改造.md) 走，并说清对装修项的影响。
- **用命令写，不手改 JSON**：`decor-edit` 只替换 `decor`，其他内容逐字节不变，写错了整批拒绝、文件不动。
- **文件里的长度和高度一律是 mm**：沙发高写 `850`，不是 `0.85`。
- **位置查出来，不要猜**：墙的 id、`side`、房间方位都从 `decor-list` 拿。
- **只讲事实**：碰到承重墙、外墙、管井，工具和命令会给事实提示。你转述事实，不替用户判断能不能做，也不写推荐尺寸、品牌、价格。
- **挖穿到墙厚算结构**，转到改造里开洞，不走装修层。

## 7.2 四步

```sh
node "$SKILL/scripts/plan-cli.mjs" decor-list "$WORK/交付/方案.json"       # 1 查：墙面、家具库、材料、风格、已有项
node "$SKILL/scripts/plan-cli.mjs" decor-edit "$WORK/交付/方案.json" "$WORK/补丁.json"   # 2 写
node "$SKILL/scripts/plan-cli.mjs" decor "$WORK/交付/方案.json"            # 3 查问题和材料粗估
node "$SKILL/scripts/plan-cli.mjs" render "$WORK/交付/方案.json" "$WORK/交付/改造后" --state renovated --include-pending   # 4 自己看一眼
```

用户开着工具并连着文件时，第 2 步写完页面自动更新（[工具连接.md](工具连接.md) 4.2）。没连着就请用户重新打开文件。

第 2 步报错时读错误文字：它会写第几条操作、哪个字段、怎么改。改补丁重试，文件不会被写坏。

- 第 3 步的完整输出很长，只想看挂没挂上和有什么问题，加 `--brief`。
- 第 4 步：方案有已确认的改造时，**一定要加 `--state renovated`**，不然出的是原始结构，没有家具。白模图看位置和形状，看不出颜色和材质。

**`decor-list` 的墙面长这样**：

```text
{ "room": "r-master", "roomName": "主卧", "dir": "南", "wall": "w-m", "side": -1, "s": [100, 4080], "wallKind": "partition", "openings": [...] }
```

`decor-list` 按**已确认的改造**算：房间名是改造后的，待确认的改造不在里面（比如还没确认的新门）。`dir` 是这面墙在这间房的哪一侧。

用户说「主卧南墙」，就用这一行的 `wall` 和 `side`。`s` 是这间房看得到的范围（离墙 a 端 mm），`height` 是这面墙的高度（「到顶」就写它），`openings` 是这面墙上的门窗，写之前先看，别压上去。一面墙可能连着几间房，会出现好几行，`s` 不同。

用户没说哪面墙时，优先没有门窗、不是承重的那面；只有承重墙可选，写 `pending` 并把事实告诉用户。

## 7.3 确认还是待确认

| 用户怎么说 | 写 | 用户看到 |
| --- | --- | --- |
| 说了做什么、做在哪（「北墙摆张三人沙发」「主卧南墙做一面到顶衣柜」）。具体尺寸是你定的也算，告诉用户定了多少 | `"status": "confirmed"` | 正常显示，标「Agent 加的」 |
| 你自己的提议；没说做在哪；话有多种理解；用户的东西尺寸是你从照片估的（「配一套」「暖一点」「做个背景板」没说哪面、「照这张图」） | `"status": "pending"`（`add` 不写也是它） | 淡紫色斜纹，标「Agent 提议」，能点「我确认」「不要这条」 |

待确认的项：

- 默认**不进** `render`（白模、深度、线稿、分割都没有），也不算进材料粗估。要看提议的效果加 `--include-pending`。
- 把已确认的项改成待确认时（`update` 写 `"status": "pending"`），命令自动存一份改前内容。用户否掉就恢复原样，不用你记。`update` 不写 `status` 就保持原来的状态。

用户怎么说就怎么做：「可以」「就这个」「留着」用 `confirm`；「不要」「其他不要」用 `reject`。

方案还没有 `decor` 时先初始化一次，后面的例子都在它之后：

```json
{ "ops": [ { "op": "init", "style": "cream" } ] }
```

## 7.4 单位和位置

| 字段 | 单位和含义 |
| --- | --- |
| `at` | 平面坐标 mm，和墙的端点同一套（y 向下） |
| `rot` | 度。0 = 正面朝屏幕下方（+y），顺时针为正 |
| `size` | `[宽, 深]` mm |
| `height`、`z` | mm。`z` 是离本层地面的高度 |
| `face` | `{ "wall": 墙id, "side": 1 或 -1 }`，墙的哪一侧。从 `decor-list` 抄，不要自己推 |
| `s` | 沿墙中心线离墙 a 端的 mm。**家具的 `wall.s` 是家具中心；柜子的 `place.s` 是柜子起点（占 `s` 到 `s + width`）；造型的 `span.s` 是起止两个数** |
| `u` | 只在造型、柜子的挖洞上用：从宿主立面左端量的 mm |

家具靠墙、挂墙不用算坐标，写 `wall`，命令替你算好（`s` 是家具**中心**的位置，`gap` 是背面离墙面的距离，`z` 是底离地的高度）。

## 7.5 操作一览

补丁是 `{ "ops": [ ... ] }`，从上到下执行，**全部成功才写入**。

| op | 字段 | 做什么 |
| --- | --- | --- |
| `init` | `style` | 方案还没有 `decor` 时初始化 |
| `style` | `style` | 换当前风格（用户明确要换才用） |
| `add` | `kind`、`item`、`status`、`wall` 或 `ceiling` | 新增。`kind`：`furniture`、`cabinet`、`panel`、`recess`、`surface`、`door`（门的外观，见 7.14）。`id` 可省略 |
| `update` | `id`、`set`、`unset`、`status` | 改字段。没写的字段和状态都不动 |
| `remove` | `id` | 删除。被别的项挂着会报错。也能删 Agent 配的风格（不是当前风格）和没人用的构件定义 |
| `confirm` | `ids` | 用户说可以 |
| `reject` | `ids` | 用户说不要：改过的恢复，新加的删除，Agent 配的风格删除 |
| `component` | `component` | 新增或替换一个自己画的构件，见 7.7 |
| `preset` | `preset` | 新增一套风格（不会自动切过去） |
| `material` | `material` | 新增材料。内置材料不用加，用到时自动复制 |
| `rehost` | 无 | 采纳 `decor` 命令算出的重挂结果，见 7.8 |

不能写 `by`（固定记成 Agent）、`ack`（只有用户在工具里点「知道了」才有）、`prev`、`cache`。

## 7.6 每类怎么写

下面的例子都用示例两室（Skill 的 `assets/example/plan.json`），能直接跑通。

**家具**：`type` 从 `decor-list` 的家具库里选，`size`、`height` 不写就用库里的常见尺寸，用户说了尺寸才写。库里没有的就自己画（7.7）。

```json
{ "ops": [
  { "op": "add", "kind": "furniture", "status": "confirmed",
    "item": { "id": "sofa-1", "type": "sofa-3", "size": [2400, 900], "height": 850 },
    "wall": { "face": { "wall": "w-w", "side": -1 }, "s": 5370, "gap": 20 } },
  { "op": "add", "kind": "furniture", "status": "pending",
    "item": { "id": "table-1", "type": "coffee-table", "at": [1900, 5370], "rot": 90, "size": [1200, 600], "height": 400 } }
] }
```

**柜体**：`family` 是 `tall`（高柜）、`base`（地柜）、`wall`（吊柜）。`columns` 从左到右（站在柜前看），`cells` 从下到上。各列 `width` 之和等于柜宽，最后一列可以不写；各格 `h` 之和等于柜高减踢脚，最上一格可以不写。`type`：`door`、`doors`、`drawers`、`flap`、`open`、`void`（挖洞，「留电视位」就是它）、`appliance`（家电位）。

主卧南墙一面到顶衣柜，中间留电视位。这面墙的 `height` 是 2800，门在 200–1100，所以从 1200 起：

```json
{ "ops": [
  { "op": "add", "kind": "cabinet", "status": "confirmed", "item": {
    "id": "wardrobe-1", "name": "主卧衣柜", "family": "tall",
    "place": { "face": { "wall": "w-m", "side": -1 }, "s": 1200 },
    "width": 2800, "depth": 600, "z": [0, 2800], "plinth": 80,
    "columns": [
      { "width": 900, "cells": [ { "type": "doors" } ] },
      { "width": 1000, "cells": [ { "type": "doors", "h": 900 }, { "type": "void", "h": 1000, "void": { "depth": 300 } }, { "type": "door" } ] },
      { "cells": [ { "type": "doors" } ] }
    ],
    "materials": { "carcass": "creamDoor", "front": "creamDoor" }, "handle": "none" } }
] }
```

用户说「宽度改成 2400」，直接改 `width`，命令让最后一列承担差值：

```json
{ "ops": [ { "op": "update", "id": "wardrobe-1", "set": { "width": 2400 }, "status": "confirmed" } ] }
```

**造型**：`type` 是 `feature`（背景墙板）、`wainscot`（护墙板）、`slats`（格栅）、`skirting`（踢脚线）、`arch`（拱形门套，写 `opening` 不写 `span`）。遇到门窗默认让开。

**壁龛和挖洞**：`niche` 挖在墙上，`depth` 必须小于墙厚；`hole` 挖在造型或柜子上，`depth` 可以写 `"through"`。

客厅东侧背景墙，板上挖一个电视位，旁边墙上再做一个壁龛（这面是承重墙，命令会给事实提示，转告用户，不拦）：

```json
{ "ops": [
  { "op": "add", "kind": "panel", "status": "confirmed", "item": {
    "id": "tv-wall", "type": "feature", "thickness": 60, "material": "oakVeneer",
    "span": { "face": { "wall": "w-d", "side": 1 }, "s": [2480, 3120], "z": [0, 2400] } } },
  { "op": "add", "kind": "recess", "status": "confirmed", "item": {
    "id": "tv-hole", "kind": "hole", "host": { "panel": "tv-wall" },
    "rect": { "u": [80, 560], "z": [900, 1500] }, "depth": "through" } },
  { "op": "add", "kind": "recess", "status": "pending", "item": {
    "id": "niche-1", "kind": "niche", "host": { "face": { "wall": "w-d", "side": 1 } },
    "rect": { "s": [3200, 3550], "z": [1000, 1600] }, "depth": 80, "shelves": [1300] } }
] }
```

**墙地顶材料**：`target` 是 `{ "floor": 房间id }`、`{ "ceiling": 房间id }`，或 `{ "face": …, "s": [..], "z": [..] }`。

- 不写 `s`、`z` 是这条墙的这一侧全部。**一面墙连着几间房时，只刷一间要写 `s`**，用 `decor-list` 这间房那一行的 `s`。
- 材料库没有用户说的（比如「灰砖」）：选最接近的并告诉用户，或者用 `material` 加一个。

卫生间的墙和地：

```json
{ "ops": [
  { "op": "add", "kind": "surface", "status": "confirmed", "item": { "id": "bath-wall", "target": { "face": { "wall": "w-c", "side": -1 } }, "material": "tileGrey" } },
  { "op": "add", "kind": "surface", "status": "confirmed", "item": { "id": "bath-floor", "target": { "floor": "r-bath" }, "material": "tileSage", "layout": { "pattern": "grid", "size": [300, 300] } } }
] }
```

**风格**：用户明确说「全屋换奶油原木」就直接换（`decor-list` 的 `styles` 里 `cream` 是奶油原木）。换风格会带动所有没单独改过的地面、墙面、顶面；单独改过的不变。`init` 没有特别要求就用 `cream`。

房间用不用湿区材料，默认按房间名或用途：含卫、厨、淋浴、浴室、马桶、盥洗、洗手、洗衣、阳台的算湿区；景观、休闲、观景阳台不算。不对就在风格的 `rooms` 里写明，比如 `"rooms": [ { "match": ["储物间"], "floor": "floor.wet", "wall": "wall.wet" } ]`，它优先于默认规则。

「配一套」就写一套新风格，让用户在工具里点「应用」。整屋提议一次给一屋，说明依据，全部待确认。这一篇不给搭配知识，也不写品牌和价格。

`roles` 能写的角色：`floor.main`、`floor.wet`、`floor.outdoor`、`threshold`、`wall.main`、`wall.wet`、`wall.accent`、`ceiling`、`skirting`、`wood.main`、`cabinet.front`、`cabinet.carcass`、`stone.top`、`metal`、`fabric.main`、`fabric.accent`、`rug`。

```json
{ "ops": [
  { "op": "style", "style": "wabi" },
  { "op": "preset", "preset": { "id": "warm-1", "name": "暖一点", "blurb": "按用户说的「暖一点，别太素」配的", "roles": { "wall.main": "cream", "floor.main": "walnut", "fabric.main": "cream" } } }
] }
```

用户在对话里确认或否掉：

```json
{ "ops": [ { "op": "confirm", "ids": ["table-1"] }, { "op": "reject", "ids": ["niche-1"] } ] }
```

## 7.7 照着画一个构件

用户说「这面墙挂一台 65 寸电视」，或者发来一张沙发、地毯、柜子的图，家具库里没有合适的，就自己画一个。先写**定义**（`component`，长什么样），再**摆放**（`add`，放哪里）。同一个定义可以摆多次。

**先定尺寸**，可信程度从高到低：用户给的 > 用户给的产品参数 > 从照片估。

- 依据写进 `basis`，比如「用户给的尺寸」「照片估算，未核实」。工具会把它显示给用户看。
- 照片是估的：先问一句有没有尺寸；没有就照估，摆放写 `pending`，并告诉用户哪几个数是估的。
- 只做「类似的」：不画商标，不写品牌型号。
- 照片只有你看，不存进方案，不发给别的服务。

**再选类别** `category`，类别决定工具里的分组，不限制能画什么：

| category | 中文 | 例子 |
| --- | --- | --- |
| `furniture` | 家具 | 沙发、桌椅、床 |
| `appliance` | 家电 | 电视、冰箱 |
| `sanitary` | 卫浴 | 马桶、浴室柜 |
| `lighting` | 灯具 | 吊灯、落地灯 |
| `plant` | 绿植 | 盆栽 |
| `soft` | 软装 | 地毯、挂画、窗帘 |
| `storage` | 收纳 | 成品柜、斗柜 |
| `ceiling` | 吊顶 | 厨卫吊顶、回字形吊顶，见 7.14 |
| `other` | 其他 | 上面都不是。必须写 `label`，比如「猫爬架」 |

要分格、开门、挖洞、嵌进墙里的柜子用 7.6 的柜体；只要外观像（成品柜、异形柜）才用构件。构件的形状用户在工具里改不了，要改就找你。

**怎么画**：每张图都是一张 SVG 画布，左上角 (0,0)，x 向右，y 向下，单位 mm。路径只写 `d` 字符串（`M L H V C S Q T A Z`），不写 `<svg>` 标签。

| 字段 | 画布 | 怎么看 |
| --- | --- | --- |
| `plan`（可选） | 宽 × 深 | 从上往下看。y=0 是**背面**（靠墙那边），y=深 是正面 |
| `front`（可选） | 宽 × 高 | 站在正面看。y=0 是**顶**，y=高 是底 |

俯视图看不出高度，所以立体靠 `parts` 表达。把东西拆成几块，每块三选一：

| 部件 | 写法 | 适合 |
| --- | --- | --- |
| 俯视轮廓加一段高度（默认） | `outline`（宽 × 深的画布）、`z: [起, 止]`，**从构件底往上量** | 桌面、桌腿、床垫、电视、地毯 |
| 侧面轮廓拉伸 | `kind:"side"`、`along`、`profile`、`span`。`along:"width"`：画侧面（深 × 高的画布），沿宽度从 `span[0]` 拉到 `span[1]`；`along:"depth"`：画正面（宽 × 高的画布），沿深度拉 | 斜靠背、躺椅、台阶 |
| 半边轮廓转一圈 | `kind:"revolve"`、`profile`（x=离轴距离，y 从顶往下；画布 半径 × 高）、`center`（可选，缺省在正中） | 花瓶、灯罩、圆凳 |

`plan` 和 `front` 只负责好看（屏幕线、抱枕线），不影响立体；不写就从 `parts` 自动生成外形。每块可以写 `color`（`#RRGGBB`）或 `material`（材料 id）。

**挂墙的电视**：一块薄板，正面画屏幕；摆放时 `z` 是离地高度。

```json
{ "ops": [
  { "op": "component", "component": {
    "id": "tv65", "name": "65 寸电视", "category": "appliance", "basis": "用户给的尺寸",
    "size": [1450, 60], "height": 830,
    "plan": [ { "d": "M0 0H1450V60H0Z", "style": "outline", "fill": "#22262c" } ],
    "front": [ { "d": "M0 0H1450V830H0Z", "style": "outline", "fill": "#22262c" }, { "d": "M16 16H1434V790H16Z", "style": "detail", "stroke": "#5a606a" } ],
    "parts": [ { "name": "机身", "outline": "M0 0H1450V60H0Z", "z": [0, 830], "color": "#22262c" } ] } },
  { "op": "add", "kind": "furniture", "status": "confirmed",
    "item": { "id": "tv-1", "type": "custom:tv65" },
    "wall": { "face": { "wall": "w-d", "side": -1 }, "s": 1830, "gap": 0, "z": 900 } }
] }
```

自己画的构件摆放时 `size`、`height` 不用写，命令从定义填。

**圆地毯**：很薄的一块，不算碰撞。

```json
{ "ops": [
  { "op": "component", "component": {
    "id": "rug-round", "name": "圆地毯", "category": "soft", "basis": "照片估算，未核实",
    "size": [1600, 1600], "height": 10,
    "parts": [ { "outline": "M1600 800A800 800 0 1 1 0 800A800 800 0 1 1 1600 800Z", "z": [0, 10], "color": "#c9b8a0" } ] } },
  { "op": "add", "kind": "furniture", "status": "pending", "item": { "id": "rug-1", "type": "custom:rug-round", "at": [2000, 5400], "rot": 0 } }
] }
```

**带斜靠背的沙发**：座是一段高度，靠背用侧面轮廓（y=0 是顶，所以靠背顶在上面）。

```json
{ "ops": [
  { "op": "component", "component": {
    "id": "sofa-slant", "name": "斜背沙发", "category": "furniture", "basis": "照片估算，未核实",
    "size": [2200, 900], "height": 800,
    "plan": [ { "d": "M0 0H2200V900H0Z", "style": "outline", "fill": "#b9b3a8" }, { "d": "M0 220H2200M733 220V900M1467 220V900", "style": "detail" } ],
    "parts": [
      { "name": "座", "outline": "M0 0H2200V900H0Z", "z": [0, 420], "color": "#b9b3a8" },
      { "name": "靠背", "kind": "side", "along": "width", "span": [0, 2200], "profile": "M0 0H120L220 380H0Z", "color": "#a9a398" } ] } }
] }
```

- 没有贴图，只有颜色。
- `front` 只在立面图上显示，不进 3D。
- 判断放不放得下时，凹形构件（L 形沙发）按外接矩形算，会偏保守。

## 7.8 拆墙之后

装修项挂在已确认改造后的结构上。用户要拆一面挂着东西的墙：

1. 照 [改造.md](改造.md) 写改造（怎么追加 `changes` 见 [工具连接.md](工具连接.md) 4.3）。`status` 的规矩按改造篇，不因为墙上有柜子就改。
2. 跑 `decor --brief`。`items` 写着每项 `placed`（没变）、`moved`（挪到了剩下的墙段）、`missing`（没地方挂）。**`decor` 只算已确认的改造**；改造还在待确认时，要看的是 `apply` 输出里的 `decor-host-missing`。
3. 把哪些挪了、哪些没地方挂，用白话告诉用户，问他要挪到哪面墙（`update`）还是删掉（`remove`）。
4. 有挪动的，用户同意后 `{"op":"rehost"}`。整面墙拆没了的项 `rehost` 救不了，要按第 3 步处理。

**没地方挂不是错误，不用为了消除它去撤改造**：数据还在，`validate`、`render`、`decor-edit` 都照常工作，只是这一项不进图，命令会提示。用户回话之前，方案就停在这个状态。

## 7.9 碰到承重墙、外墙、管井

嵌进墙、壁龛这类操作碰到承重墙、外墙、承重柱、管井时，`issues` 里有事实提示。

- 原样转述，比如「这面在图上是承重墙，嵌入要现场找专业确认」。不说「可以做」或「不能做」。
- 用户在工具里点「知道了」只表示看过，事实不解除，改造清单照样列进「需要专业确认」。

## 7.10 问题码

`decor` 里是下表的码；`validate`、`apply`、`decor-edit` 里前面多一个 `decor-`（`protected` 写成 `decor-protected`）：

| 码 | 级别 | 意思 |
| --- | --- | --- |
| `unit-suspect` | error | 数值不合理，多半把 mm 写成了 m；或者摆放的尺寸和定义不一致 |
| `component-invalid` | error | 构件定义有错：路径不对、超出画布、高度段越界、`other` 缺 `label`，文字里写了第几块 |
| `component-missing` | error | `custom:<id>` 找不到定义 |
| `duplicate-id` | error | id 重复 |
| `material-missing` | error | 材料 id 不存在 |
| `invalid` | error | 字段形状不对，包括柜列宽度之和不等于柜宽 |
| `host-missing`、`host-cut` | 这次写入造成的：error；拆墙留下的：warn | 挂的墙不存在、被拆或超出范围，见 7.8 |
| `out-of-face`、`too-deep`、`through-wall`、`meet-other-side`、`host-depth` | 多为 error | 超出墙面、挖得太深、挖穿了（挖穿转改造） |
| `over-opening` | 靠墙摆、挂墙：warn；嵌进墙：error | 靠墙的柜子、家具挡住门窗，把事实告诉用户，不拦。嵌进墙的部分撞到洞口做不了，要挪开 |
| `protected`、`wall-kind`、`into-shaft` | warn | 碰到承重、外墙、管井，见 7.9 |
| `unknown-type` | warn | 家具库没有这个 type，会画成通用盒子。按提示换一个，或自己画 |

## 7.11 交接文字

用户在工具里选中构件点「交给 Agent」时，交接文字模式是「装修」，后面有一段 `## 装修构件（ref）`，每个构件一条，长这样：

```text
- 柜体 wardrobe-1 / 主卧衣柜；w-m（隔墙）……。
  数据：{ "id": "wardrobe-1", "family": "tall", "width": 2800, … }
```

用 id 定位，用「用户原话」判断要改什么，然后 `decor-edit`。方案文件是绝对路径才能改，见 [工具连接.md](工具连接.md) 4.3。

## 7.12 交付时怎么说

- 效果图要反映方案：写好装修后 `render --state renovated` 出素材，再走 [生图.md](生图.md)。默认只画已确认的，用户想看提议的效果才加 `--include-pending`，并说清图里有还没确认的东西。
- 材料粗估是按面积算的用量参考，不是报价，也不是施工下料。
- 不说「放得下」「没问题」这种结论：工具给的是净距和重叠事实，说事实。

## 7.13 常见错误

| 错误 | 现象 | 怎么办 |
| --- | --- | --- |
| 高度写成 m（`0.85`） | `unit-suspect` | 全部写 mm（`850`） |
| `side` 写反 | 东西贴到墙背面的房间 | 从 `decor-list` 抄这间房那一行 |
| `s` 和 `u` 混用 | 校验报错或位置偏 | 墙上用 `s`，造型、柜子上的洞用 `u` |
| 柜列宽度之和不对 | `invalid` | 最后一列不写 `width` |
| 柜子的 `s` 写成中心 | `host-cut`，超出连续墙面 | 柜子的 `s` 是起点 |
| 拆墙后想消除 `decor-host-missing` | 把改造退回去 | 不用退，见 7.8 |
| 构件 `z` 当成离地高度 | 构件被拉得很高 | `parts` 的 `z` 从构件底量，离地高度写在摆放的 `z` |
| `front` 的 y 当成离地高度 | 正面图上下颠倒 | y=0 是顶 |
| `profile` 上下颠倒 | 靠背、灯罩倒了 | y=0 是顶，先想顶在哪 |
| 重写整个方案来改一处 | 其他字段丢失 | 只用 `decor-edit` |

## 7.14 门、吊顶、灯、木工造型

**做法都一样**：白模只管轮廓和位置，木纹、肌理、灯光这些写进 `look`（一句白话，300 字以内），`gen_prompt.py` 会把它写进生图提示词。不要为了纹理去画很细的路径，近处的细线反而容易被当成结构。`look` 能写在构件定义、家具、柜体、造型、壁龛和门的外观上；摆放项写了就优先于定义。

**门**分两件事：

- 开法、宽高、平开还是推拉、移不移位置，是结构，按 [改造.md](改造.md) 走。
- 颜色、材质、门板样子，用 `kind:"door"` 写外观。`opening` 从 `decor-list` 的 `openings` 里抄。`front` 的画布是洞口宽 × 洞口高，y=0 是顶。门洞没有门扇，不能写外观，要做门套用下面的拱形门套。

```json
{ "ops": [
  { "op": "add", "kind": "door", "status": "confirmed", "item": {
    "id": "door-master", "name": "主卧门", "opening": "o-master", "color": "#6b4a33",
    "frame": { "color": "#5a3e2b" },
    "look": "胡桃木平板门，极窄门框，黑色细把手",
    "front": [ { "d": "M100 150H800V950H100ZM100 1150H800V1950H100Z", "style": "detail" } ] } }
] }
```

**弧形门洞**：用造型 `arch` 在原门洞上做门套，只在洞口范围里收，不改洞口。要真的改洞口大小走改造。

```json
{ "ops": [
  { "op": "add", "kind": "panel", "status": "pending", "item": {
    "id": "arch-bath", "type": "arch", "opening": "o-bath", "thickness": 60, "material": "white",
    "look": "白色石膏拱形门套，线条干净" } }
] }
```

**吊顶**（`category:"ceiling"`）：画俯视轮廓和厚度，摆放写 `ceiling`，高度命令算好，构件顶贴到顶面。`at` 不写就放在房间正中。厨卫吊顶就是一整块，一般吊顶常见回字形（外圈一层，中间挖孔）。要跌级就多写几块，每块自己的轮廓和高度段。

    "item": { "id": "ceil-1", "type": "custom:ceil-living", "at": [3000, 5400] },

- 主灯：画一个简化的形状（常用转一圈），`look` 写样子。
